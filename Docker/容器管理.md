# 容器

## 容器的结构

1. **运行时架构**

   ```
   ┌───────────────────────┐
   │     Container RW      │  # 容器可写层（日志/临时文件等）
   ├───────────────────────┤
   │     Image Layers      │  # 共享镜像的只读层
   └───────────────────────┘
   ```

2. **核心组件**

   - 可写层（容器层）：存储运行时产生的所有修改
   - 挂载点（Volume）：持久化数据存储区域
   - 命名空间（Namespace）：隔离的进程/网络视图
   - 控制组（Cgroup）：资源限制单元

## 容器和镜像对比

| 特性         | 镜像(Image)            | 容器(Container)           |
| :----------- | :--------------------- | :------------------------ |
| **本质**     | 只读的模板文件包       | 镜像的运行实例            |
| **状态**     | 静态不可变             | 动态可读写                |
| **存储**     | 分层存储（Layer）      | 容器层（可写层）          |
| **生命周期** | 长期存在               | 临时性（可随时创建/删除） |
| **数量关系** | 一个镜像可生成多个容器 | 容器必须基于某个镜像      |

## 容器和镜像的关系

1. **创建过程**

   ![deepseek_mermaid_20250817_4257de](.\images\deepseek_mermaid_20250817_4257de.png)

2. **存储关系**

   - 镜像层：所有容器共享的只读部分

   - 容器层：每个容器独有的可写层

   - 典型磁盘使用：

     ```shell
     $ docker system df
     TYPE        TOTAL     ACTIVE    SIZE      RECLAIMABLE
     Images      3         2         1.2GB     500MB
     Containers  2         1         25MB      25MB
     ```

3. **生命周期交互**

   - 删除镜像需先删除依赖容器
   - 容器修改可通过`docker commit`生成新镜像
   - 镜像更新需重建容器才能生效

# 容器管理

## 创建容器

用于创建一个新的容器但不自动启动它

~~~shell
docker create [选项] 镜像 [命令] [参数...]
~~~

**选项**

- **基础选项**
  - **-d, --detach**：后台运行容器
  - **--name**：为容器指定名称
  - **-it**：交互模式运行（通常组合使用：`-i`保持STDIN打开，`-t`分配伪终端）
  - **--rm**：容器退出时自动删除
- **资源限制**
  - **-m, --memory**：内存限制（如：`-m 512m`）
  - **--memory-swap**：内存+交换分区限制
  - **--cpus**：CPU核心数限制（如：`--cpus=1.5`）
  - **--cpu-shares**：CPU权重（默认1024）
- **网络配置**
  - **-p, --publish**：端口映射（格式：`主机端口:容器端口`）
  - **-P, --publish-all**：发布所有暴露的端口
  - **--network**：指定网络（如：`--network=bridge`）
  - **--hostname**：设置容器主机名
- **存储卷**
  - **-v, --volume**：挂载卷（格式：`主机路径:容器路径[:选项]`）
  - **--mount**：更详细的挂载方式
  - **--tmpfs**：挂载临时文件系统
- **环境变量**
  - **-e, --env**：设置环境变量（如：`-e MYSQL_ROOT_PASSWORD=123456`）
  - **--env-file**：从文件读取环境变量
- **安全选项**
  - **--cap-add**：添加Linux能力
  - **--cap-drop**：删除Linux能力
  - **--read-only**：以只读模式运行容器
  - **--security-opt**：安全选项

> **注意**
>
> 1. 与`docker run`不同，`create`只创建容器不自动启动
> 2. 容器状态会显示为"Created"（可通过`docker ps -a`查看）
> 3. 创建后需使用`docker start`启动容器
> 4. 适合需要精细控制容器启动流程的场景
> 5. 所有设置选项与`docker run`命令基本一致

## 运行容器

用于创建并立即启动一个新的容器

```shell
docker run [选项] 镜像 [命令] [参数...]
```

**选项** 

- **运行模式**
  - **-d, --detach**：后台运行容器
  - **-it**：交互模式运行（组合使用：`-i`保持STDIN打开，`-t`分配伪终端）
  - **--rm**：容器退出时自动删除

- **容器配置**
  - **--name**：为容器指定名称
  - **--hostname**：设置容器主机名
  - **--restart**：设置重启策略（no, on-failure, always, unless-stopped）
  - **--workdir**：设置容器内工作目录

- **资源限制**
  - **-m, --memory**：内存限制（如：`-m 512m`）
  - **--memory-swap**：内存+交换分区限制
  - **--cpus**：CPU核心数限制（如：`--cpus=1.5`）
  - **--cpu-shares**：CPU权重（默认1024）

- **网络配置**
  - **-p, --publish**：端口映射（格式：`主机端口:容器端口`）
  - **-P, --publish-all**：发布所有暴露的端口
  - **--network**：指定网络模式
  - **--add-host**：添加主机到IP映射（格式：`host:ip`）
  - **--dns**：设置自定义DNS服务器

- **存储卷**
  - **-v, --volume**：挂载卷（格式：`主机路径:容器路径[:选项]`）
  - **--mount**：更详细的挂载方式
  - **--tmpfs**：挂载临时文件系统

- **环境变量**
  - **-e, --env**：设置环境变量
  - **--env-file**：从文件读取环境变量

- **安全选项**
  - **--cap-add**：添加Linux能力
  - **--cap-drop**：删除Linux能力
  - **--security-opt**：安全选项
  - **--read-only**：以只读模式运行容器


> **注意**
>
> 1. 这是最常用的容器操作命令
> 2. 如果本地不存在指定镜像，会自动从仓库拉取
> 3. 默认在前台运行（除非使用`-d`选项）
> 4. 容器停止后默认会保留（除非使用`--rm`选项）
> 5. 使用`-it`可进入交互式shell
> 6. 端口映射必须使用`-p`参数显式声明
> 7. 数据卷挂载需要使用绝对路径

## 重启容器

用于重启一个或多个正在运行的容器

```shell
docker restart [选项] 容器 [容器...]
```

**选项**

- **-t, --time**：设置停止超时时间（单位：秒，默认10秒）
- **--signal**：发送自定义信号给容器（默认SIGTERM）
- **-h, --help**：显示帮助信息

> **注意**
>
> 1. 会先停止容器再重新启动（不是热重启）
> 2. 容器将使用最初创建时的相同配置重新启动
> 3. 对已停止的容器执行会直接启动它
> 4. 重启期间服务会有短暂中断
> 5. 适用于配置更新后需要重新加载的场景
> 6. 与`docker stop`+`docker start`组合效果相同，但更原子化

## 停止容器

用于停止一个或多个运行中的容器

```shell
docker stop [选项] 容器 [容器...]
```

**选项**

- **-t, --time**：设置停止超时时间（单位：秒，默认10秒）
- **--signal**：发送自定义信号给容器（默认SIGTERM）
- **-h, --help**：显示帮助信息

> **注意**
>
> 1. 默认会先发送SIGTERM信号，超时后发送SIGKILL强制终止
> 2. 停止的容器可以通过`docker start`重新启动
> 3. 容器停止后会保留所有文件系统和配置
> 4. 使用`-t/--time`可以调整优雅停止的等待时间
> 5. 对已停止的容器执行不会产生任何效果
> 6. 与`docker kill`相比更优雅（允许进程完成清理工作）

## 列出容器

用于列出容器

```shell
docker ps [选项]
```

**选项**

- **-a, --all**：显示所有容器（默认只显示运行中的）
- **-f, --filter**：根据条件过滤输出
  - `status=running|created|restarting|paused|exited|dead`
  - `name=容器名称`
  - `id=容器ID`
  - `label=key`或`label=key=value`
  - `ancestor=镜像名`（使用指定镜像创建的容器）
  - `before`/`since=容器`（时间/容器关系）
- **--format**：使用Go模板格式化输出
- **-n, --last**：显示最后创建的n个容器（包括所有状态）
- **-l, --latest**：显示最新创建的容器（包括所有状态）
- **--no-trunc**：不截断输出
- **-q, --quiet**：只显示容器ID
- **-s, --size**：显示容器大小（文件系统）
- **--since**：显示在指定容器/时间之后创建的容器
- **--until**：显示在指定容器/时间之前创建的容器
- **-h, --help**：显示帮助信息

**输出字段说明**

| 字段         | 说明                           |
| :----------- | :----------------------------- |
| CONTAINER ID | 容器唯一标识（SHA256的前12位） |
| IMAGE        | 创建容器使用的镜像             |
| COMMAND      | 容器启动时运行的命令           |
| CREATED      | 容器创建时间                   |
| STATUS       | 运行状态（Up/Exited/Paused等） |
| PORTS        | 端口映射情况                   |
| NAMES        | 容器名称                       |

> **注意**
>
> 1. 默认输出包含：容器ID、镜像、命令、创建时间、状态、端口、名称
> 2. 停止的容器会显示退出状态码（非0通常表示错误）
> 3. 使用`--format`可以完全自定义输出格式
> 4. 过滤条件可以组合使用，如`-f "name=web" -f "status=running"`
> 5. 在生产环境中建议配合`-q`选项用于脚本处理

## 挂起/恢复容器

用于暂停/恢复容器中所有进程的执行

```shell
docker pause 容器 [容器...]
docker unpause 容器 [容器...]
```

**选项** 

- **无特殊选项**：这两个命令通常不需要额外选项

**相关命令对比** 

| 命令    | 效果     | 资源占用 | 恢复速度     |
| :------ | :------- | :------- | :----------- |
| `pause` | 冻结进程 | 保持占用 | 即时恢复     |
| `stop`  | 终止进程 | 释放资源 | 需要重新启动 |
| `kill`  | 强制终止 | 完全释放 | 需要重新启动 |

> **注意**
>
> 1. `pause`会冻结容器内的所有进程（使用cgroups freezer功能）
> 2. 暂停的容器仍会占用系统资源（内存等），只是进程被挂起
> 3. 暂停状态可通过`docker ps`查看（显示为Paused）
> 4. 网络连接在暂停期间会保持但无响应
> 5. 与`docker stop`不同，暂停可以快速恢复且不终止进程
> 6. 适用于临时冻结容器状态而不想停止容器的场景

## 进入容器

用于在运行中的容器内执行命令

```shell
docker exec [选项] 容器 命令 [参数...]
```

**选项**

- **基础选项** 
    - **-d, --detach**：后台运行命令
    - **-e, --env**：设置环境变量
    - **-i, --interactive**：保持STDIN打开（即使未连接）
    - **-t, --tty**：分配伪终端（通常与-i一起使用）
    - **-u, --user**：指定执行用户（格式：用户名或UID）
- **工作目录** 
    - **-w, --workdir**：设置命令的工作目录
- **其他选项** 
    - **--env-file**：从文件读取环境变量
    - **--privileged**：赋予扩展权限
    - **--index**：对多个实例容器指定索引（默认1）

> **注意**
>
> 1. 容器必须处于运行状态（Running）才能使用exec
> 2. 使用`-it`组合可进入交互式会话（类似SSH）
> 3. 执行的命令会继承容器的环境变量
> 4. 退出交互会话不会停止容器（与`docker attach`不同）
> 5. 适合调试、维护或执行一次性任务
> 6. 对容器文件系统的修改会持久化

## 导入容器

用于从归档文件创建镜像

```shell
docker import [选项] 文件|URL - [镜像名:标签]
```

**选项**

- **-c, --change**：应用Dockerfile指令（如`CMD`/`ENV`等）
- **-m, --message**：设置提交信息
- **--platform**：设置平台（如`linux/amd64`）

> **注意**
>
> 1. 通常与`docker export`配合使用
> 2. 导入的镜像不保留原始历史层和元数据
> 3. 可通过`-c`设置基本的Dockerfile指令
> 4. 镜像名必须包含`-`或`:`才能自动添加标签

## 导出容器

用于将容器文件系统导出为tar归档

```shell
docker export [选项] 容器 > 输出文件.tar
```

**选项** 

- **-o, --output**：指定输出文件（替代重定向）

**示例** 

```shell
docker export -o /opt/nginx.tar nginx-2
```

> **注意**
>
> 1. 导出的是容器快照，不包含历史层
> 2. 与`docker save`不同，只导出文件系统不包含元数据
> 3. 导出的内容可通过`docker import`重新创建镜像
> 4. 运行中的容器也可以导出（但可能导致数据不一致）

## 查看容器日志

用于查看容器的日志输出

```shell
docker logs [选项] 容器
```

**选项**

- **输出控制** 
    - **-f, --follow**：实时跟踪日志输出
    - **--tail**：显示最后N行日志（如`--tail 100`）
    - **-t, --timestamps**：显示时间戳
    - **--since**：显示某个时间之后的日志（如`--since 2023-01-01`）
    - **--until**：显示某个时间之前的日志
- **格式化** 
    - **--details**：显示额外的详细信息
    - **-n, --max-logs**：设置最大显示日志条数
- **其他** 
    - **--timestamps**：显示日志时间戳
    - **--utc**：使用UTC时间格式

> **注意**
>
> 1. 默认显示容器STDOUT和STDERR的输出
> 2. 容器必须正在运行或已停止（无法查看已删除容器的日志）
> 3. 日志驱动需为`json-file`或`journald`（其他驱动可能不支持）
> 4. 使用`-f`时按Ctrl+C退出跟踪模式
> 5. 日志大小和保留策略可通过`docker run`的`--log-*`参数控制

## 删除容器

用于删除一个或多个容器

```shell
docker rm [选项] 容器 [容器...]
```

**选项**

- **-f, --force**：强制删除运行中的容器（默认只能删除停止的容器）
- **-v, --volumes**：同时删除关联的匿名卷
- **-l, --link**：删除指定的容器链接（已废弃）
- **--filter**：根据条件过滤要删除的容器
- **-q, --quiet**：只显示容器ID（用于脚本处理）

> **注意**
>
> 1. 默认只能删除停止状态（`exited`）的容器
> 2. 使用`-f`强制删除会发送SIGKILL终止运行中的容器
> 3. 删除容器会同时移除其读写层（但不会删除镜像）
> 4. 命名卷（named volume）默认不会被删除（除非显式使用`docker volume rm`）
> 5. 重要数据应提前备份
