# 镜像

Docker 镜像是 Docker 技术的核心组件之一，它是容器化应用的**静态模板**，包含了运行应用所需的完整环境和依赖

## 镜像的本质

1. **只读模板**

   - 镜像一旦创建便不可修改（immutable）
   - 所有变更通过创建新层实现

2. **分层存储结构**

   <img src=".\images\deepseek_mermaid_20250817_a1b12e.png" alt="deepseek_mermaid_20250817_a1b12e" style="zoom:25%;" />

   - 每层只存储与上一层的差异（节约空间）
   - 联合文件系统（如 overlay2）实现层叠加

3. **内容寻址存储**

   - 每个层由 SHA256 哈希唯一标识
   - 确保镜像内容完整性

## 镜像核心组成

| 组成部分     | 说明                             | 示例                                                 |
| :----------- | :------------------------------- | :--------------------------------------------------- |
| **基础镜像** | 底层操作系统或运行时环境         | `ubuntu:20.04`, `python:3.9`                         |
| **环境配置** | 系统变量、工作目录、暴露端口等   | `ENV PATH=/usr/bin`, `EXPOSE 8080`                   |
| **依赖文件** | 应用程序代码、库文件、配置文件等 | `COPY . /app`, `RUN pip install -r requirements.txt` |
| **启动命令** | 容器启动时执行的默认命令         | `CMD ["python", "app.py"]`                           |

# 镜像标签

## 什么是镜像标签

Docker 镜像标签（Tag）是用于标识和区分不同版本镜像的元数据，相当于给镜像起的"别名"。每个标签都指向一个具体的镜像ID（SHA256哈希值）。

## 标签的组成结构

```
[仓库地址/][命名空间/]镜像名:标签
```

**完整格式解析**

- **仓库地址**（可选）：默认是Docker Hub（`docker.io`），私有仓库如`registry.example.com` 
- **命名空间**（可选）：用户或组织名称，如 `library/`（官方镜像）
- **镜像名**（必需）：如`nginx`、`ubuntu`
- **标签**（可选）：默认 `latest`，如 `1.23.0`、`alpine` 

## 创建命令

```shell
docker image tag 源镜像[:标签] 新镜像名[:标签]
```

> **注意**
>
> 1. 标签操作不会创建新镜像，只是新增引用
> 2. 同一镜像ID可对应多个标签
> 3. 推送镜像前必须正确打标签

## 标签的核心特性

1. **多标签指向同一镜像**

   ```shell
   # 给已有镜像添加新标签
   docker tag nginx:1.23 my-nginx:latest
   ```

   - 不会创建新镜像，只是新增引用
   - 可通过 `docker image inspect` 查看所有关联标签

2. **标签版本控制**

   - 语义化版本：`v1.2.3` 
   - 构建时间：`20230815` 
   - 环境标识：`prod`/`test` 

3. **特殊标签规则**

   - `latest`：默认标签（不推荐生产环境使用）
   - `alpine`：基于Alpine Linux的轻量版本
   - `slim`：精简版本（移除非必要组件）

## 标签管理规范

### 命名建议

```shell
# 推荐格式
[项目名]-[版本号]-[环境]-[构建号]
示例：order-service-1.2.0-prod-b123
```

# 镜像管理

## 搜索镜像

用于从Docker Hub或其他镜像仓库搜索镜像

```shell
docker search [选项] 关键词
```

**选项** 

- **--limit**：限制返回结果数量（默认25）
- **--filter**：按条件过滤结果
- **--format**：自定义输出格式
- **--no-trunc**：显示完整的描述信息
- **--stars**：仅显示至少X星标的镜像（如`--stars=100`）
- **--is-official**：仅显示官方镜像
- **--is-automated**：仅显示自动构建的镜像

## 下载镜像

用于从镜像仓库拉取镜像到本地

```shell
docker pull [选项] 镜像名[:标签]
```

**选项**

- **-a, --all-tags**：下载仓库中所有标签的镜像
- **--platform**：指定平台（如 `linux/amd64`）
- **--quiet**：静默模式，仅输出镜像ID

> **注意**
>
> 1. 默认从Docker Hub拉取
> 2. 不指定标签时默认使用`:latest`
> 3. 私有仓库需先`docker login`
> 4. 下载进度条显示各层(layer)下载情况


##  镜像列表

查看本地镜像仓库内容

```shell
docker image ls [选项]
```

**选项**

- **显示控制**
  - **-a, --all**：显示所有镜像（包括中间层）
  - **-q, --quiet**：仅显示镜像ID
  - **--no-trunc**：显示完整的镜像ID（不截断）
- **信息筛选**
  - **--digests**：显示镜像摘要（Digest）
  - **--filter**：按条件过滤镜像（如`dangling=true`）
  - **--format**：使用Go模板自定义输出格式
- **排序与限制**
  - **--sort**：按指定字段排序（如`--sort=size`）
  - **--limit**：限制显示结果数量（Docker 23.0+）

**输出字段**

- REPOSITORY：镜像仓库名称（包含用户/组织名前缀）
- TAG：镜像标签（版本标识）
- IMAGE ID：镜像唯一标识（SHA256哈希的前12位）
- CREATED：镜像创建时间（相对时间或绝对时间）
- SIZE：镜像总大小（包含所有层）

**特殊状态说明**

- **`<none>`标记**：表示悬空镜像（Dangling images），通常是构建过程中的中间层或旧版本镜像
- **`missing`标记**：表示本地镜像的某些层已丢失（需重新拉取）

**注意**

> 1. `IMAGE ID`为SHA256的前12位
> 2. 悬空镜像（`<none>`）可通过`docker image prune`清理
> 3. 使用`--no-trunc`显示完整ID


## 镜像信息

查看镜像详细信息


```shell
docker image inspect 镜像名/ID
```

**输出内容**

- 完整配置（环境变量、入口点等）
- 分层信息
- 创建时间
- 父镜像
- 容器配置


## 镜像创建信息

查看镜像构建历史记录

```shell
docker image history 镜像名/ID
```

**选项**

- **--no-trunc**：显示完整命令
- **-q, --quiet**：仅显示层ID
- **--human**：人性化显示大小


## 导出镜像

将镜像保存为tar归档文件

```shell
docker image save -o 文件名.tar 镜像名[:标签]
```

**选项**

- **-o, --output**：指定输出文件
- **--compress**：启用压缩

> **注意**
>
> 1. 导出包含镜像的所有层和元数据
> 2. 适合镜像迁移或备份
> 3. 文件较大，建议配合压缩使用


## 导入镜像

从tar文件加载镜像到本地仓库

```shell
docker image load -i 文件名.tar
```

**选项**

- **-i, --input**：指定输入文件
- **-q, --quiet**：静默模式

**与 `docker import` 区别** 

| 特性     | `load`                 | `import`              |
| :------- | :--------------------- | :-------------------- |
| 来源     | 由`save`导出的完整镜像 | 文件系统归档（如tar） |
| 保留历史 | 是                     | 否                    |
| 适用场景 | 镜像备份恢复           | 从rootfs创建基础镜像  |


## 删除镜像

移除本地镜像

```shell
docker rmi 镜像名/ID
# 或
docker image rm 镜像名/ID
```

**选项**

- **-f, --force**：强制删除（即使有容器使用该镜像）
- **--no-prune**：保留悬空的父镜像（不自动清理）
- **--filter**：按条件过滤要删除的镜像
- **-q, --quiet**：只显示被删除的镜像ID

> **注意**
>
> 1. 默认无法删除正在被容器使用的镜像（需先删除容器或使用`-f`）
> 2. 删除镜像会同时移除其所有关联的标签
> 3. 镜像分层存储中未被其他镜像引用的层会被自动清理
> 4. 重要数据应确保已通过卷(volume)持久化
> 5. 删除操作不可逆，建议先备份重要镜像

# 仓库管理

## 公共仓库

### 官方Docker仓库

- [**Docker Hub**](https://hub.docker.com/) 官网
- 官网注册账号并登录
- 填写完账户基本信息
- 使用 `docker login docker.io` 输入用户密码就可以连接到官方仓库

**缺点** 

- 国内可能因为网络问题难以连接

### 阿里云镜像仓库

1. [**Aliyun Hub**](https://cr.console.aliyun.com/) 官网
2. 阿里云仓库注册账号并登录
3. 容器镜像服务->实例列表->镜像仓库->创建镜像仓库
4. 执行操作指南

```shell
# 1.登录阿里云Docker Registry
$ docker login --username='USERNAME' registry.cn-hangzhou.aliyuncs.com
# 2.从Registry中拉取镜像
$ docker pull [镜像URL]:[镜像版本号]
# 3.将镜像推送到Registry
$ docker login --username='USERNAME' registry.cn-hangzhou.aliyuncs.com
$ docker tag [ImageId] [镜像URL]:[镜像版本号]
$ docker push [镜像URL]:[镜像版本号]
# 4.选择合适的镜像仓库地址: 公网访问/VPC网络内访问
```

## 私有仓库

### docker registry

1. [**Distribution地址**](https://github.com/distribution/distribution) 官方Github地址
2. docker register作为Docker的核心组件之一负责镜像内容的存储与分发，客户端的docker pull以及push命令都将直接与register进行交互
3. docker register由初代的python开发改为了更安全的Go开发（新的docker register被称为Distribution）
