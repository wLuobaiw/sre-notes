# git init

用于在指定目录初始化新的本地 Git 仓库，生成隐藏的 `.git` 文件夹（存储版本库核心数据）

```bash
git init [选项] [目录]
```

**选项**

- **-q, --quiet**：安静模式，减少初始化过程的输出信息，仅显示必要提示
- **--bare**：创建 “裸仓库”（仅包含版本库数据，无工作区，本地开发极少使用，多用于服务器）
- **--initial-branch <name>**：指定仓库的初始分支名称（默认值为 `main`，替代老版本的 `master`）
- **--template <dir>**：使用自定义模板目录初始化仓库（可预设忽略规则、钩子脚本等）
- **--separate-git-dir <dir>**：将 `.git` 目录存储到指定路径（分离工作区和版本库）
- **-h, --help**：显示帮助信息

> **注意**
>
> 1. 已初始化的目录重复执行 `git init` 不会覆盖现有版本库，仅更新部分配置
> 2. 初始化后 `.git` 文件夹默认隐藏，Windows 需显示隐藏文件才能查看
> 3. 目录默认为当前目录

# git status

用于查看本地仓库的文件状态，明确文件处于「工作区 / 暂存区 / 版本库」的哪个阶段（未跟踪、已修改、待提交等）

```bash
git status [选项]
```

**选项**

- **-s, --short**：简洁输出格式（一行显示一个文件的状态码 + 文件名）
- **--long**：详细输出格式（默认格式，包含文件状态说明）
- **--ignored**：显示被 `.gitignore` 规则忽略的文件 / 目录
- **--untracked-files=<mode>**：控制未跟踪文件的显示规则
  - `no`：不显示未跟踪文件
  - `normal`：默认，显示未跟踪的文件和目录
  - `all`：显示未跟踪目录下的所有文件
- **--porcelain**：机器可读的标准化输出格式（适合脚本解析）
- **-b, --branch**：额外显示当前分支及与远程分支的差异
- **-h, --help**：显示帮助信息

> **注意**
>
> 1. 中文文件名显示乱码时，可执行 `git config --global core.quotepath false` 修复
> 2. 执行 `git status` 是排查文件状态问题的首要步骤
> 3. 无额外参数时，默认显示当前目录下所有文件的状态

# git add

将文件从工作区添加到暂存区（Index / Stage），为下一次提交做准备

```bash
git add [选项] [路径...]
```

**选项**

- **-A, --all**：添加所有修改（包括删除），等价于 `git add --all`
- **-u, --update**：仅添加已跟踪文件的修改和删除，不包含未跟踪新文件
- **-p, --patch**：交互式选择要暂存的修改块（hunk），逐块确认是否添加
- **-f, --force**：强制添加被 `.gitignore` 忽略的文件
- **-n, --dry-run**：仅显示哪些文件会被添加，不实际执行
- **-v, --verbose**：显示详细信息
- **-i, --interactive**：进入交互式暂存模式（子命令：status / update / revert 等）
- **--ignore-errors**：忽略无法添加的文件的错误，继续处理其余文件
- **--renormalize**：根据 `.gitattributes` 重新规范化行尾符（CRLF / LF）
- **--chmod=+x | --chmod=-x**：设置文件的可执行权限

> **注意**
>
> 1. `git add .` 只添加当前目录及子目录的修改
> 2. `git add -A` 会添加整个仓库的所有修改（包括删除），等价于 `git add --all`
> 3. 配合 `git status` 使用，先看状态，再决定 add 什么
> 4. 使用 `-p` 可以精细控制哪些修改进入本次提交

# git commit

将暂存区的修改提交到本地版本库，形成一次版本记录（snapshot）

```bash
git commit [选项] [文件...]
```

**选项**

- **-m, --message="msg"**：直接指定提交信息，跳过编辑器
- **-a, --all**：跳过 `git add`，自动暂存所有已跟踪文件的修改并提交（不包含未跟踪文件）
- **-v, --verbose**：在提交信息编辑器中显示完整的 diff，辅助编写信息
- **--amend**：修改最近一次提交（追加暂存区修改到上次提交，不产生新提交）
- **--no-edit**：配合 `--amend` 使用，保持原提交信息不变
- **--allow-empty**：允许创建空提交（无文件变更）
- **--allow-empty-message**：允许提交信息为空
- **-S, --gpg-sign**：使用 GPG 签名提交，验证提交者身份
- **--date="date"**：覆盖提交日期

> **注意**
>
> 1. 提交信息应清晰说明 "做了什么" 和 "为什么"
> 2. `--amend` 会改写历史，不要对已推送的远程提交使用
> 3. 空提交可用于触发 CI/CD 流程
> 4. 建议每次提交聚焦一个功能点，避免大而全的提交

# git log

查看提交历史记录

```bash
git log [选项] [范围...]
```

**选项**

输出格式：
- **--oneline**：一行显示一条提交（精简 SHA + 提交信息）
- **--graph**：用 ASCII 图显示分支合并历史
- **--decorate**：显示分支名、标签名等引用（默认开启）
- **--stat**：显示每次提交修改的文件统计
- **-p, --patch**：显示每次提交的完整 diff
- **--format="..."**：自定义输出格式（如 `"%h - %an, %ar : %s"`）

过滤筛选：
- **-n, --max-count=N**：只显示最近 N 条提交
- **--author="name"**：按作者筛选
- **--since="date" / --until="date"**：按时间范围筛选
- **--grep="pattern"**：按提交信息关键字筛选
- **--no-merges**：不显示合并提交
- **文件名**：仅显示涉及指定文件的提交

其他：
- **--all**：显示所有分支的提交
- **--follow**：跟踪文件重命名历史（配合文件名使用）
- **-S "code"**：搜索添加 / 删除了指定代码的提交

> **注意**
>
> 1. `git log --oneline --graph --all` 是最常用的组合，直观展示分支结构
> 2. 按 `q` 退出 log 查看
> 3. 可组合多个筛选条件精准定位提交

# git diff

查看文件修改的具体内容（按行对比差异）

```bash
git diff [选项] [<源>...<目标>]
```

常用场景：
- **`git diff`**：工作区 vs 暂存区（看还没 add 的修改）
- **`git diff --staged`（或 `--cached`）**：暂存区 vs HEAD（看即将提交的内容）
- **`git diff HEAD`**：工作区 vs HEAD（看所有未提交的修改）
- **`git diff 分支A..分支B`**：两个分支的差异
- **`git diff commit1 commit2`**：两个提交的差异

**选项**

- **--stat**：仅显示文件统计（哪些文件变了、增减行数）
- **--name-only**：仅显示变更的文件名
- **--name-status**：显示文件名及状态（M = 修改、A = 新增、D = 删除）
- **--word-diff**：按单词粒度显示差异（而非按行）
- **-w, --ignore-all-space**：忽略空白字符变化
- **--cached / --staged**：比较暂存区和 HEAD

> **注意**
>
> 1. 每次 commit 前建议执行 `git diff --staged` 确认要提交的内容
> 2. 按 `q` 退出 diff 查看
> 3. 可指定具体文件路径只查看该文件的差异

# git reset

将当前分支的 HEAD 指针回退到指定版本，可选是否保留工作区 / 暂存区修改

```bash
git reset [模式] [目标]
```

三种模式（核心区别）：

| 模式 | HEAD 移动 | 暂存区 | 工作区 | 典型场景 |
| :--- | :-------: | :----: | :----: | :------- |
| --soft | ✓ | 保留 | 保留 | 合并多个 commit 为一个 |
| --mixed（默认） | ✓ | 重置 | 保留 | 撤销 `git add` / 撤销 commit |
| --hard | ✓ | 重置 | 重置 | 彻底回到某个版本（危险！） |

目标写法：
- **HEAD^**：上一个版本，`HEAD^^`：上上个版本
- **HEAD~N**：回退 N 个版本（如 `HEAD~3`）
- **版本号**：写前 6-8 位即可（如 `8a7b2c9`）

> **注意**
>
> 1. `--hard` 会**永久丢失**工作区和暂存区的未提交修改，使用前务必确认
> 2. 已推送到远程的提交，reset 后需 `git push --force` 同步（协作分支禁用！）
> 3. 误操作可用 `git reflog` 找回丢失的提交（30 天内）

# git restore

恢复工作区或暂存区的文件到指定版本的状态（Git 2.23+，是 `git checkout` 文件恢复功能的现代替代）

```bash
git restore [选项] [文件...]
```

常用场景：
- **`git restore 文件名`**：丢弃工作区修改，恢复到暂存区状态
- **`git restore --staged 文件名`**：把文件从暂存区撤回工作区（撤销 `git add`）
- **`git restore --source=HEAD~1 文件名`**：将文件恢复到上一个版本
- **`git restore --source=版本号 文件名`**：将文件恢复到指定版本

**选项**

- **-s, --source="tree"**：从指定来源恢复（默认：暂存区或 HEAD）
- **-S, --staged**：恢复暂存区内容
- **-W, --worktree**：恢复工作区内容（默认行为）
- **--ours / --theirs**：合并冲突时，选择保留当前分支 / 合并分支的版本

> **注意**
>
> 1. 丢弃工作区修改不可逆，恢复前建议用 `git diff` 确认
> 2. 相比旧命令 `git checkout -- 文件`，语义更清晰（restore = 恢复）
> 3. `git restore` 不会移动 HEAD，仅恢复文件内容

# git rm

从版本库和工作区中删除文件，并将删除操作添加到暂存区

```bash
git rm [选项] 文件...
```

**选项**

- **--cached**：仅从版本库中移除（停止跟踪），保留工作区文件
- **-r**：递归删除目录
- **-f, --force**：强制删除（文件有未暂存的修改时）
- **-n, --dry-run**：仅显示哪些文件会被删除，不实际执行
- **--ignore-unmatch**：即使无匹配文件也不报错

> **注意**
>
> 1. 普通 `git rm` 会同时删除版本库记录和工作区文件
> 2. `git rm --cached` 适合 "忘记跟踪某文件" 的场景（如误提交了 `.env`）
> 3. 删除后仍需 `git commit` 完成版本记录
> 4. 与直接 `rm` + `git add` 效果相同，但 `git rm` 更简洁

# git mv

移动或重命名文件，并将操作添加到暂存区

```bash
git mv [选项] <源> <目标>
```

**选项**

- **-f, --force**：强制移动（目标已存在时覆盖）
- **-n, --dry-run**：仅显示结果，不实际执行
- **-v, --verbose**：显示详细信息
- **-k**：跳过会导致错误的操作

> **注意**
>
> 1. Git 会自动检测重命名（即使使用普通 `mv` + `git add`）
> 2. `git mv` 等价于 `mv 旧名 新名 && git add 旧名 新名`
> 3. 移动后仍需 `git commit` 完成版本记录
> 4. 配合 `git log --follow 文件名` 可追溯重命名前的历史
