
# 线程

线程是**CPU 调度的最小单位**，一个进程可以包含多个线程。同一进程的各线程共享地址空间和文件描述符，但各自有独立的栈和寄存器上下文。

**为什么需要线程？** 进程在同一时间只能做一件事。如果要同时处理键盘输入、界面刷新、自动保存，多进程太重（切换开销大），多线程共享数据更轻量。

# 进程 vs 线程

| 特性 | 进程 | 线程 |
|------|------|------|
| 资源 | 独立地址空间、文件描述符 | 共享进程资源、独立栈 |
| 创建/切换开销 | 大 | 小 |
| 通信 | IPC（管道、socket、共享内存） | 直接读写共享数据（需同步） |
| 隔离性 | 强——一个进程崩溃不影响其他 | 弱——一个线程崩溃可能带崩整个进程 |
| 调度 | 操作系统按进程调度 | 操作系统按线程调度 |

# 协程（Coroutine）

协程是**用户态**的轻量级并发单元，由程序自身控制调度，非操作系统调度。

| 特性 | 线程 | 协程 |
|------|------|------|
| 调度者 | 操作系统内核 | 用户程序（runtime） |
| 切换开销 | 系统调用 + 上下文切换 | 用户态函数调用级别 |
| 并发数 | 受限于内存和调度开销 | 单线程可维护数千协程 |
| 并发模型 | 抢占式（随时被 OS 中断） | 协作式（主动让出执行权） |
| 适用场景 | CPU 密集型 | IO 密集型（网络请求、文件读写） |

常见实现：Python 的 `asyncio`、Go 的 goroutine、Kotlin 的 coroutine。

> **核心理解**：进程是资源分配单位，线程是 CPU 调度单位，协程是用户态并发抽象。三者不是替代关系，而是不同层次的并发方案。
