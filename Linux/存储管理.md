# 什么是存储管理

## 初识Linux存储管理

当你刚开始接触Linux系统时，可能会对"存储管理"这个概念感到困惑。简单来说，存储管理就是操作系统如何组织、使用和维护计算机的存储设备（如硬盘、U盘等）的一套方法。就像图书馆需要管理书籍的存放位置一样，Linux也需要管理文件在存储设备上的存放方式。

### 存储设备在Linux中的呈现

在Linux中，所有的硬件设备（包括存储设备）都是以**文件**的形式呈现的。这种"一切皆文件"的设计理念是Linux的核心特点之一：

1. **物理设备映射**：
   - 你的硬盘不会显示为"C盘"、"D盘"这样的概念
   - 而是被识别为`/dev/sda`、`/dev/sdb`这样的设备文件
2. **设备文件位置**：
   - 所有的设备文件都存放在`/dev`目录下
   - 存储设备通常以`sd`(SCSI/SATA)或`nvme`(NVMe SSD)开头
3. **访问方式**：
   - 你可以像操作普通文件一样查看设备信息
   - 例如：`ls -l /dev/sd*`可以列出所有的SCSI/SATA设备

### 为什么需要存储管理？

想象你的电脑是一间空仓库，存储管理就是解决以下问题：

1. **空间划分**：如何把大仓库分成多个区域（分区）
2. **物品存放规则**：每个区域使用什么货架系统（文件系统）
3. **权限控制**：谁可以存取哪些区域（配额管理）
4. **效率优化**：如何快速找到所需物品（磁盘调度）

## 常见疑惑

-  **Windows有C盘、D盘，Linux的"盘"在哪里？** 
  Linux使用"挂载点"概念，比如你的硬盘可能被挂载到`/home`目录下作为用户文件存储位置

-  **为什么插入U盘后找不到？** 
  需要先挂载设备，通常会被自动挂载到`/media/用户名/设备名`目录下

-  **Linux会像Windows一样产生磁盘碎片吗？** 
  Linux的文件系统设计不同，碎片问题很少，一般不需要手动整理

# 硬盘设备命名

 ## 传统 IDE/PATA 硬盘

- **命名格式**: `hd[a-z]`
  - **分区命名**:
    - 主分区: `hda1`-`hda3`
    - 扩展分区: `hda4`
    - 逻辑分区: `hda5`开始

- **示例**:
  - `/dev/hda1` (第一个主分区)
  - `/dev/hda4` (扩展分区)
  - `/dev/hda5` (第一个逻辑分区)
- **特点**:
  - 逐渐淘汰，现代系统更多使用 SATA/SCSI 命名规则

## SATA/SCSI/SAS/USB 硬盘

- **命名格式**: `sd[a-z]`

  - **分区命名**:
    - 主分区: `sda1`-`sda3`
    - 扩展分区: `sda4`
    - 逻辑分区: `sda5`开始
      - 完全包含在扩展分区内
      - 数量理论上无限制（实际受系统约束）
      - 编号从 **5开始**（1-4保留给主分区）
      - 通过扩展分区内的 **二级分区表** 管理

- **示例**:

  - `/dev/sdb1` (第二块硬盘的第一个主分区)
  - `/dev/sdb5` (第二块硬盘的第一个逻辑分区)



## NVMe SSD

- **命名格式**: `nvme[0-9]n[0-9]`
  - **分区命名**:
    - 主分区: `nvme0n1p1`-`nvme0n1p3`
    - 扩展分区: `nvme0n1p4`
    - 逻辑分区: `nvme0n1p5`开始
- **示例**:
  - `/dev/nvme0n1p1` (第一个NVMe设备的第一个主分区)
  - `/dev/nvme0n1p5` (第一个NVMe设备的第一个逻辑分区)

## 虚拟设备

- **命名格式**: `vd[a-z]`
  - **分区命名**:
    - 主分区: `vda1`-`vda3`
    - 扩展分区: `vda4`
    - 逻辑分区: `vda5`开始
- **示例**:
  - `/dev/vdb2` (第二个虚拟硬盘的第二个主分区)

## 其他物理设备命名

| 硬件设备 |     文件名称       |
| ------ | ------------------ |
| 软驱   | /dev/fd[0-1]       |
| 打印机 | /dev/lp[0-15]      |
| 光驱   | /dev/cdrom         |
| 鼠标   | /dev/mouse         |
| 磁带机 | /dev/st0或/dev/ht0 |

# 分区表

分区表是存储在磁盘起始扇区中的数据结构，用于记录磁盘的分区布局（如分区数量、大小、类型等）。它相当于磁盘的“目录”，告诉操作系统如何访问和管理不同分区。

## 分区表作用

- **定义分区边界**：记录每个分区的起始和结束位置（柱面/扇区）。
- **标识分区类型**：如 NTFS、FAT32、Linux swap 等。
- **支持多系统启动**：允许不同操作系统共存于同一磁盘的不同分区。
- **保护数据隔离**：防止一个分区的错误影响其他分区。

## 分区表类型

### MBR（Master Boot Record）

- **分区命名**

  MBR 的分区命名遵循 **主分区 + 扩展分区 + 逻辑分区** 的规则

  - **主分区**：编号 **1-4**（如 `/dev/sda1`、`/dev/sda2`）
  - **扩展分区**：占用 **1 个主分区号**（通常是 `4`，如 `/dev/sda4`）
  - **逻辑分区**：从 **5 开始编号**（如 `/dev/sda5`、`/dev/sda6`）

    ~~~tex
    sda1 (主分区，20GB)
    sda2 (主分区，30GB)
    sda3 (主分区，50GB)
    sda4 (扩展分区，100GB)
      ├─ sda5 (逻辑分区，30GB)
      ├─ sda6 (逻辑分区，40GB)
      └─ sda7 (逻辑分区，30GB)
    ~~~

- **特点**：
  - 传统分区表，兼容性极强（支持 BIOS 启动）
  - 最大支持 **2TB** 磁盘，最多 **4个分区**
    - 有两种情况
      - 四个主分区
      - 三个主分区 + 一个扩展分区
    - 扩展分区：内部可以划分**多个逻辑分区**，但是所有逻辑分区在分区表中都算在一个分区内
  - 分区信息存储在磁盘的第一个扇区（512字节）

- **结构**：
  - **引导代码**（前446字节）：用于启动操作系统
  - **分区表**（64字节）：记录4个分区的信息
  - **结束标志**（2字节：`0x55AA`）

### GPT（GUID Partition Table）

- **分区命名**

  GPT **没有主/扩展/逻辑分区的概念**，所有分区都是 **主分区**，编号从 **1 开始连续递增**：

  - **SATA/SCSI/SAS/USB 硬盘**：`/dev/sd[a-z][分区号]`（如 `/dev/sda1`、`/dev/sda2`）
  - **NVMe SSD**：`/dev/nvme[控制器号]n[命名空间号]p[分区号]`（如 `/dev/nvme0n1p1`、`/dev/nvme0n1p2`）
  - **虚拟硬盘**：`/dev/vd[a-z][分区号]`（如 `/dev/vda1`、`/dev/vda2`）

  ```tex
  /dev/sda1  (EFI 系统分区)
  /dev/sda2  (根分区 /)
  /dev/sda3  (/home 分区)
  /dev/sda4  (交换分区 swap)
  ```

- **特点**：

  - 现代分区表，支持 **UEFI 启动**。
  - 最大支持 **18EB（艾字节）** 磁盘，理论上无限分区数量（实际限制由操作系统决定）。
  - 具有冗余备份，更安全。

- **结构**：
  - **保护性MBR**（兼容旧系统）。
  - **GPT头**：记录分区表位置和校验信息。
  - **分区条目数组**：每个条目128字节，可包含多个分区。
  - **备份GPT头**：防止主分区表损坏。

### 类型对比

| **特性**         | **MBR**                          | **GPT**                          |
| :--------------- | :------------------------------- | :------------------------------- |
| **最大磁盘容量** | 2TB                              | 18EB（1EB=1024PB）               |
| **最大分区数量** | 4个主分区（或扩展分区+逻辑分区） | 理论上无限（Windows限制为128个） |
| **启动方式**     | 仅支持 BIOS                      | 支持 UEFI 和 BIOS（需兼容模式）  |
| **安全性**       | 无校验，易损坏                   | CRC校验，备份分区表              |
| **兼容性**       | 所有操作系统                     | 较新系统（Windows Vista+/Linux） |

# 文件系统

当我们在硬盘上完成分区后，还需要为这些分区建立一套"管理规则"——这就是文件系统。简单来说，文件系统决定了数据在磁盘上的存储和读取方式，就像图书馆需要一套图书分类管理系统一样。

## 文件系统的核心作用

文件系统主要解决三个关键问题：

1. **存储规范**：数据应该按照什么格式存放
2. **读取规则**：如何快速准确地找到所需数据
3. **空间管理**：如何高效利用磁盘空间

## Linux文件系统的主要类型

虽然Linux支持数十种文件系统，但主要分为两大类：

### 日志式文件系统

- **特点**：记录操作日志，意外断电时能快速恢复
- **代表**：ext4、XFS、Btrfs
- **适用场景**：需要高可靠性的场景

- **特点**：通过索引结构快速定位文件
- **代表**：NTFS、FAT32
- **适用场景**：兼容性要求高的场景

## 主流 Linux 文件系统

### Ext3 (Third Extended File System)

**特点：**

- 日志式文件系统，提供数据一致性保障
- 系统异常宕机时可避免文件系统资料丢失
- 自动修复数据不一致与错误

**局限性：**

- 硬盘容量大时修复时间较长
- 不能100%保证资料不丢失
- 记录整个磁盘的每个写入动作细节

### Ext4 (Fourth Extended File System)

**改进点：**

- RHEL 6默认文件系统
- 支持高达1EB(约10亿GB)的存储容量
- 支持无限数量的子目录
- 批量分配block块，提高读写效率
- 引入"extents"概念，减少文件碎片

**技术参数：**

- 最大文件大小：16TB
- 最大文件系统大小：1EB

### XFS (X File System)

**优势：**

- RHEL 7默认文件系统
- 高性能日志文件系统
- 宕机后能快速恢复
- 日志功能性能开销低
- 支持高达18EB的存储容量

**特点：**

- 特别适合大文件处理
- 延迟分配策略减少碎片
- 并行I/O操作

### Btrfs (B-Tree File System)

- 先进的文件系统，支持许多现代特性
- 功能包括：
  - 写时复制(CoW)
  - 快照
  - 内置RAID支持
  - 子卷
  - 透明压缩

### ZFS

- 最初由Sun Microsystems开发
- 特性：
  - 存储池概念
  - 数据完整性校验
  - 自动修复
  - 极高的可扩展性

### Swap（交换分区）

- 特殊文件系统用于虚拟内存
- 当物理内存不足时使用
- 在生产环境中，交换分区的大小一般为真实物理内存的1.5～2倍

## 文件系统核心概念

### 格式化过程

- **日志式文件系统**：先清除inode表
- **索引式文件系统**：先清除第一个索引，标记空间可用

### 关键数据结构

#### Superblock (超级块)

- 记录文件系统整体信息
- 包含：
  - inode/block的总量、使用量、剩余量
  - 文件系统格式及相关信息

#### Inode (索引节点)

- 记录文件属性，每个文件占用一个inode
- 默认大小：128字节
- 记录文件数据所在的block号码
- 包含信息：
  - 访问权限(r/w/x)
  - 所有者与所属组
  - 文件大小
  - 时间戳(ctime/atime/mtime)
  - 特殊权限(SUID/SGID/SBIT)
  - 真实数据地址指针
- 当记录满时会新建inode扩展

#### Block (数据块)

- 实际存储文件数据的单元
- 大小通常为1KB、2KB或4KB

## 虚拟文件系统(VFS)

**作用：**

- 为用户程序提供统一接口
- 屏蔽不同文件系统的底层差异

**优势：**

- 用户无需关心底层硬盘结构
- 支持多种文件系统共存
- 提供一致的文件操作API

# 磁盘容量配额

简单理解就是可以通过磁盘配额限制某个用户能够使用多大的空间

## Quota

### 限制类型

`quota` 有三种限制类型

- **硬限制(Hard Limit)**：绝对不允许超过的限制值
- **软限制(Soft Limit)**：允许暂时超过的限制值，但会有宽限期
- **宽限期(Grace Period)**：超过软限制后允许继续使用的缓冲时间(默认7天)

### 应用场景

- 多用户系统中防止单个用户占用过多空间
- 虚拟主机环境中限制客户网站使用的资源
- 教育或企业环境中公平分配存储资源

### 常用命令

#### quotacheck

用于扫描文件系统并检查磁盘配额的使用情况，创建/更新配额文件(aquota.user和aquota.group)

```shell
quotacheck [选项] 文件系统
```

**选项**

- **-a, --all**：检查所有在/etc/mtab中启用了配额的文件系统
- **-c, --create-files**：强制创建新的配额文件（会覆盖现有文件）
- **-d, --debug**：启用调试模式输出详细信息
- **-f, --force**：强制检查（即使文件系统看似干净）
- **-F, --format=格式**：指定配额格式(vfsv0/vfsv1)
- **-g, --group**：只检查组配额
- **-i, --interactive**：交互模式（显示每个文件系统的确认提示）
- **-m, --no-remount**：不尝试重新挂载文件系统为只读
- **-M, --try-remount**：尝试以读写方式重新挂载（某些只读文件系统可能失败）
- **-n, --use-first-dquot**：当检测到冲突时使用第一个发现的配额
- **-R, --exclude-root**：不检查根文件系统（与-a一起使用时）
- **-u, --user**：只检查用户配额（默认行为）
- **-v, --verbose**：显示详细处理信息
- **-b, --backup**：在修改配额文件前创建备份
- **-h, --help**：显示帮助信息
- **-V, --version**：显示版本信息

> **注意**
>
> 1. 需要root权限执行
> 2. 执行前应确保没有进程正在写入目标文件系统
> 3. 对于挂载的文件系统，内核可能要求以只读方式重新挂载才能进行检查
> 4. 检查大型文件系统可能较耗时
> 5. 完成后通常需要运行`quotaon`启用配额
> 6. 建议将quotacheck加入cron定期执行（如每周一次）

#### edquota

用于编辑用户或组的磁盘配额限制

```shell
edquota [选项] [用户名/组名]
```

**选项**

- **-u, --user**：编辑用户配额（默认行为）
- **-g, --group**：编辑组配额
- **-p, --prototype=原型用户**：将原型用户的配额设置复制给其他用户
- **-t, --edit-period**：编辑宽限期（用户超出软限制后的允许时间）
- **-f, --filesystem**：指定要操作的文件系统
- **-r, --remote**：编辑远程文件系统的配额（需RPC支持）
- **-F, --format=格式**：指定配额格式(vfsv0/vfsv1)
- **-h, --help**：显示帮助信息
- **-V, --version**：显示版本信息

> **注意**
>
> 1. 需要root权限执行
> 2. 会启动默认文本编辑器（通过VISUAL或EDITOR环境变量指定）
> 3. 可同时设置块限制（磁盘空间）和inode限制（文件数量）
> 4. 软限制可被临时超出，硬限制是绝对上限
> 5. 使用-p选项可批量设置多个用户配额

#### quota

显示用户或组的磁盘使用情况和限制

```shell
quota [选项] [用户名/组名]
```

**选项**

- **-u, --user**：显示用户配额（默认行为）
- **-g, --group**：显示组配额
- **-v, --verbose**：显示详细信息（包括未使用的配额）
- **-s, --human-readable**：以易读格式显示（如1K, 234M等）
- **-f, --filesystem**：只显示指定文件系统的配额
- **-i, --no-autofs**：忽略autofs挂载点
- **-l, --local-only**：只显示本地文件系统
- **-Q, --quiet**：不显示错误信息
- **-h, --help**：显示帮助信息
- **-V, --version**：显示版本信息

> **注意**
>
> 1. 普通用户只能查看自己的配额
> 2. root用户可以查看所有用户/组的配额
> 3. 输出包含使用量、软限制、硬限制和宽限期
> 4. 未显示配额可能表示该文件系统未启用配额

#### repquota

汇总显示文件系统的配额使用情况

```shell
repquota [选项] [文件系统]
```

**选项**

- **-a, --all**：显示所有已挂载文件系统的配额
- **-u, --user**：显示用户配额（默认行为）
- **-g, --group**：显示组配额
- **-v, --verbose**：显示详细输出（包括未使用的配额）
- **-s, --human-readable**：以易读格式显示大小
- **-c, --batch-translation**：批量转换UID/GID为名称（性能更好）
- **-t, --truncate-names**：截断过长的用户名/组名
- **-n, --no-names**：显示原始UID/GID而不解析名称
- **-F, --format=格式**：指定配额格式(vfsv0/vfsv1)
- **-h, --help**：显示帮助信息
- **-V, --version**：显示版本信息

> **注意**
>
> 1. 需要root权限执行
> 2. 输出包含所有用户/组的配额使用情况汇总
> 3. 对大型系统建议使用-s选项提高可读性
> 4. 常用于生成配额使用报告

#### setquota

命令行方式直接设置磁盘配额（无需交互编辑）

```shell
setquota [选项] 名称 块软限制 块硬限制 inode软限制 inode硬限制 文件系统
```

**选项**

- **-u, --user**：设置用户配额
- **-g, --group**：设置组配额
- **-F, --format=格式**：指定配额格式(vfsv0/vfsv1)
- **-r, --remote**：设置远程文件系统配额
- **-p, --prototype**：从原型用户复制配额设置
- **-b, --batch**：批量模式（从标准输入读取多行设置）
- **-h, --help**：显示帮助信息
- **-V, --version**：显示版本信息

> **注意**
>
> 1. 需要root权限执行
> 2. 适合在脚本中自动设置配额
> 3. 设置0表示无限制
> 4. 块限制单位通常是KB
> 5. 比edquota更适合批量操作

#### quotaon/quotaoff

启用或禁用文件系统的配额功能

```shell
quotaon [选项] [文件系统...]
quotaoff [选项] [文件系统...]
```

**公共选项**

- **-a, --all**：操作所有在/etc/mtab中启用了配额的文件系统
- **-v, --verbose**：显示详细操作信息
- **-h, --help**：显示帮助信息
- **-V, --version**：显示版本信息

**quotaon专用选项**

- **-u, --user**：启用用户配额（默认）
- **-g, --group**：启用组配额
- **-F, --format=格式**：指定配额格式(vfsv0/vfsv1)

**quotaoff专用选项**

- **-u, --user**：禁用用户配额（默认）
- **-g, --group**：禁用组配额
- **-p, --print-state**：只显示当前状态而不改变

> **注意**
>
> 1. 需要root权限执行
> 2. 通常在系统启动时自动执行quotaon
> 3. 修改配额设置后需要重新启用才能生效
> 4. 禁用配额会停止所有配额检查
> 5. XFS文件系统总是启用配额（只能通过mount选项控制）
