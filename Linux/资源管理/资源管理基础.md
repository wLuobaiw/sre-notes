
# 资源隔离 vs 资源限制

Linux 内核提供了两种互补的资源管控机制：

| 机制 | 作用 | 回答什么问题 |
|------|------|------------|
| **namespace** | 资源隔离 | "能看到什么"——进程 A 能不能看到进程 B 的文件/网络/进程 |
| **cgroup** | 资源限制 | "能用多少"——这个进程组最多能用多少 CPU、多少内存 |

两者组合就是**容器**的技术基础——namespace 让容器以为自己独占系统，cgroup 确保容器不会占用所有资源。

# namespace 简介

namespace 给进程创建独立的系统资源视图。Linux 有 8 种 namespace：

| namespace | 隔离内容 |
|-----------|---------|
| Mount | 文件系统挂载点 |
| PID | 进程编号 |
| Network | 网络设备、IP、端口 |
| User | 用户/组 ID |
| IPC | 进程间通信 |
| UTS | 主机名 |
| Cgroup | cgroup 文件系统视图 |
| Time | 系统时钟 |

一个进程默认共享宿主机所有 namespace；容器进程拥有独立的 namespace 集合。

# cgroup 简介

cgroup（控制组）将进程分组，对每组统一施加资源限制：

| 控制器 | 限制什么 |
|--------|---------|
| cpu | CPU 使用配额 |
| memory | 内存使用上限 |
| blkio/io | 磁盘 IO 速度 |
| pids | 进程数量上限 |
| cpuset | CPU 核心绑定 |
| devices | 设备访问控制 |

**cgroup v2** 是当前标准（RHEL 8+、Ubuntu 22.04+ 默认）。

# namespace + cgroup + rootfs = 容器

```
容器
├── namespace  → "我能看到什么"（隔离的文件系统、网络、进程...）
├── cgroup     → "我能用多少资源"（CPU、内存、IO 限制）
└── rootfs     → "我有哪些文件"（镜像层组成根文件系统）
```
