
# 主流 Linux 文件系统

| 文件系统 | 特点 | 适用场景 |
|----------|------|---------|
| **ext4** | 成熟稳定，最大 1EB，支持日志 | 通用场景，RHEL 6 默认 |
| **XFS** | 高性能，大文件优化，最大 18EB | 大文件存储，RHEL 7+ 默认 |
| **Btrfs** | 快照、压缩、写时复制、内置 RAID | 高级存储需求 |
| **ZFS** | 存储池、数据校验、自动修复 | 数据完整性要求高 |
| **Swap** | 虚拟内存 | 物理内存不足时换出 |

## ext4 vs XFS

| 特性 | ext4 | XFS |
|------|------|-----|
| 缩容 | 支持 | **不支持** |
| 日志 | 元数据+数据日志 | 元数据日志 |
| 大文件性能 | 一般 | 优秀 |
| 大量小文件 | 良好 | 一般 |

> RHEL 7 及之后版本默认 XFS。对于数据库、大文件存储选 XFS；需要缩容灵活性选 ext4。

# 核心数据结构

| 结构 | 作用 |
|------|------|
| **Superblock（超级块）** | 记录文件系统整体信息：大小、空闲量、inode 数量 |
| **Inode（索引节点）** | 每个文件一个 inode——记录权限、大小、时间、数据块地址 |
| **Block（数据块）** | 实际存储文件内容，通常 1KB/2KB/4KB |
| **VFS（虚拟文件系统）** | 内核抽象层——为用户程序提供统一的文件操作接口 |

# mkfs——创建文件系统（格式化）

```shell
mkfs.ext4 /dev/sdb1
mkfs.xfs /dev/sdb1 -f       # -f 强制覆盖已有文件系统
mkfs -t ext4 /dev/sdb1
mkswap /dev/sdb2             # 创建 swap 区域
swapon /dev/sdb2             # 启用 swap
```

> 格式化会**永久清除**分区的所有数据——确认设备名称正确。

# mount / umount——挂载与卸载

## mount——挂载文件系统

```shell
mount /dev/sdb1 /mnt/data           # 基本挂载
mount -t ext4 /dev/sdb1 /mnt/data   # 指定文件系统类型
mount -o ro /dev/sdb1 /mnt/data     # 只读挂载
mount -o remount,rw /mnt/data       # 重新挂载为读写
mount -a                             # 挂载 /etc/fstab 中所有条目
```

## umount——卸载

```shell
umount /mnt/data         # 按挂载点卸载
umount /dev/sdb1         # 按设备卸载
umount -l /mnt/data      # 延迟卸载——断开连接，等不忙时清理
umount -f /mnt/data      # 强制卸载（NFS 等网络文件系统）
```

## 常用挂载选项（-o 参数）

| 选项 | 作用 |
|------|------|
| `ro` / `rw` | 只读 / 读写 |
| `noexec` | 禁止执行二进制文件 |
| `nosuid` | 忽略 SUID/SGID 位 |
| `nodev` | 不解释设备文件 |
| `noatime` | 不更新 atime——减少 IO |
| `defaults` | 默认选项：rw, suid, dev, exec, auto, nouser, async |

# /etc/fstab——开机自动挂载

```ini
# 设备         挂载点   类型   选项           dump  fsck顺序
/dev/sdb1      /data    ext4   defaults,noatime  0     2
UUID=abc123... /boot    xfs    defaults          0     0
```

| 字段 | 含义 |
|------|------|
| 设备 | 设备路径或 UUID（推荐 UUID——设备名可能变化） |
| 挂载点 | 目录路径 |
| 类型 | 文件系统类型 |
| 选项 | 挂载选项，多个用逗号分隔 |
| dump | 是否备份（0=不备份） |
| fsck 顺序 | 0=不检查，1=根文件系统先检查，2=其他后检查 |

查看 UUID：`blkid /dev/sdb1`

修改 `/etc/fstab` 后先执行 `mount -a` 验证，确认无误再重启——错误的 fstab 可能导致系统无法启动。

# quota——磁盘配额

限制某用户或组在文件系统中能使用的空间和文件数量。

## 关键概念

- **硬限制**：绝对不允许超过的上限
- **软限制**：允许暂时超过，在**宽限期**（默认 7 天）内必须降回软限制以下
- **宽限期**：用户超过软限制后的缓冲时间

## 启用流程

```shell
# 1. 挂载时开启配额（/etc/fstab 加选项）
# /dev/vg_data/lv_home /home ext4 defaults,usrquota,grpquota 0 0

mount -o remount /home

# 2. 创建配额文件
quotacheck -cug /home

# 3. 启用配额
quotaon /home

# 4. 设置配额
edquota -u username      # 交互编辑用户配额
setquota -u username 50000 55000 0 0 /home   # 脚本设置：块软/硬限制，inode软/硬限制
```

## 查看配额

```shell
quota -u username       # 查看用户配额使用情况
repquota /home          # 汇总显示文件系统配额
```

## 关闭配额

```shell
quotaoff /home
```

> 注意：XFS 文件系统的配额在 mount 时自动启用（无需 quotaon），但配额管理命令通用。

# 注意

- 生产环境 swap 大小建议：物理内存 ≤ 2GB 时 swap=2×RAM；2-8GB 时 swap=RAM；>8GB 时 swap=4-8GB
- 卸载前确保没有进程在使用：`lsof /mnt/data` 或 `fuser -vm /mnt/data`
- fstab 中推荐使用 UUID 而非设备路径——设备名可能因硬件顺序变化
- 重要数据分区建议开启 usrquota 防止单用户占满磁盘
