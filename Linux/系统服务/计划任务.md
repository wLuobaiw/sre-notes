
# crontab——定时任务

crontab 是 Linux 最常用的定时任务调度工具。每个用户可以有自己的 crontab 文件。

## 命令

```shell
crontab -e          # 编辑当前用户的定时任务
crontab -l          # 查看当前用户的定时任务
crontab -r          # 删除当前用户的所有定时任务
crontab -u username -e  # root 编辑指定用户的定时任务
```

## Cron 时间格式

```
分 时 日 月 周 命令
│  │  │  │  │  │
│  │  │  │  │  └── 要执行的命令或脚本
│  │  │  │  └──── 星期（0-7，0和7都表示周日）
│  │  │  └─────── 月份（1-12）
│  │  └────────── 日期（1-31）
│  └───────────── 小时（0-23）
└──────────────── 分钟（0-59）
```

## 时间表达式示例

```shell
# 每天凌晨 2:00 执行备份
0 2 * * * /opt/scripts/backup.sh

# 每 5 分钟检查一次服务状态
*/5 * * * * /opt/scripts/health_check.sh

# 每周一早上 8:30 发送周报
30 8 * * 1 /opt/scripts/weekly_report.sh

# 每月 1 号凌晨 1:00 清理日志
0 1 1 * * /opt/scripts/clean_logs.sh

# 每小时的第 15 分钟
15 * * * * /opt/scripts/hourly.sh

# 工作日（周一至周五）每小时
0 * * * 1-5 /opt/scripts/workday_hourly.sh
```

## 时间表达式特殊写法

| 写法 | 等效 | 说明 |
|------|------|------|
| `@reboot` | - | 系统启动时执行一次 |
| `@yearly` / `@annually` | `0 0 1 1 *` | 每年 1 月 1 日 0:00 |
| `@monthly` | `0 0 1 * *` | 每月 1 日 0:00 |
| `@weekly` | `0 0 * * 0` | 每周日 0:00 |
| `@daily` / `@midnight` | `0 0 * * *` | 每天 0:00 |
| `@hourly` | `0 * * * *` | 每小时整点 |

## 注意事项

1. **PATH**：cron 的环境变量与登录 Shell 不同——crontab 中的命令要用绝对路径或在脚本中设置 PATH
2. **日志**：cron 的错误输出默认通过邮件发送给用户（如系统未配置邮件——静默丢失）。建议在命令中显式重定向：
   ```shell
   0 2 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1
   ```
3. **% 字符**：crontab 中 `%` 是特殊字符（表示换行），需要转义为 `\%`
4. **重叠执行**：如果一个任务的执行时间超过间隔，可能多个实例同时运行——脚本内部加锁（如 `flock`）防护

# 系统级定时任务

除了用户 crontab，还有系统级定时任务目录：

```shell
/etc/crontab            # 系统级 crontab（格式多一个 user 字段）
/etc/cron.d/            # 系统定时任务碎片（包管理器放这里）
/etc/cron.hourly/       # 每小时执行的脚本
/etc/cron.daily/        # 每天执行的脚本
/etc/cron.weekly/       # 每周执行的脚本
/etc/cron.monthly/      # 每月执行的脚本
```

# at——一次性定时任务

```shell
# 1 小时后执行
at now + 1 hour
at> /path/to/command
at> Ctrl+D

# 指定具体时间
at 2:30 PM tomorrow
at 10:00 2026-12-31

# 查看待执行任务
atq

# 删除指定任务
atrm <任务编号>
```

# systemd timer（替代 cron）

systemd 提供了与 cron 功能相当的 timer 单元，优势是与 systemd 生态集成：

- 日志直接进入 journald（无需自己重定向）
- 可以精确到秒（cron 只到分钟）
- 可以指定依赖关系（如必须在某个 service 启动后才能运行）

timer 的详细配置见 [systemd与systemctl](../进程管理/systemd与systemctl.md)。

# Cron vs systemd timer

| 特性 | cron | systemd timer |
|------|------|------|
| 最小精度 | 分钟 | 秒 |
| 日志 | 需自行重定向 | 自动进入 journald |
| 随机延迟 | 需要 sleep hack | 内置 RandomizedDelaySec |
| 依赖管理 | 脚本内自行处理 | 可声明 After/Wants |
| 复杂度 | 低——一行配置 | 需要写两个 unit 文件 |

简单定时任务用 cron 方便；需要日志追踪、依赖管理、秒级执行时考虑 systemd timer。
