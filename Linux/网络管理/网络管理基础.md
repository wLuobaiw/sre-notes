
# TCP/IP 协议栈概览

从实用角度，Linux 运维最常接触的协议层：

| 层 | 协议 | 运维关注点 |
|----|------|----------|
| 应用层 | HTTP/HTTPS、DNS、SSH、NTP | 服务端口、配置文件 |
| 传输层 | TCP、UDP | 连接状态（`ss`）、端口监听 |
| 网络层 | IP、ICMP | 路由表（`ip route`）、连通性（`ping`） |
| 链路层 | Ethernet、ARP | 网卡（`ip link`）、MAC 地址 |

> 纯网络理论（TCP 拥塞控制、BGP 协议细节等）不在本目录展开。这里只聚焦 Linux 系统上的网络配置和诊断。

# 网络接口

Linux 中每个网络接口有一个名称：

| 接口 | 说明 |
|------|------|
| `lo` | 回环接口——127.0.0.1，本机内部通信 |
| `eth0` / `ens33` | 物理网卡——命名规则因发行版和 udev 规则而异 |
| `docker0` | Docker 虚拟网桥 |
| `veth*` | 虚拟网卡对——连接容器和网桥 |

查看所有接口：`ip link show` 或 `ifconfig -a`

# 数据包流转路径

以本机访问外部网站为例，数据包经过的 iptables 链：

```
本机发出：OUTPUT → POSTROUTING → 网卡 → 网络
本机接收：网络 → 网卡 → PREROUTING → INPUT
转发：    网络 → 网卡 → PREROUTING → FORWARD → POSTROUTING → 网卡 → 网络
```

这就是 iptables 的五条链——每条链对应数据包生命周期中的一个检查点。

# iptables 与 SELinux 的角色

- **[iptables](./iptables基础.md)**：网络层防火墙——控制哪些包能进、能出、能被转发。Kubernetes Service 的负载均衡底层就是 iptables 的 DNAT 规则。
- **[SELinux](./SELinux.md)**：系统层强制访问控制——在比传统权限更底层的位置控制进程能访问哪些文件、端口、设备。常与 iptables 配合形成纵深防御。
