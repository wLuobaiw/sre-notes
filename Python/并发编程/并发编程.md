
# 进程、线程、协程

三者是不同粒度的执行单元：

```
进程（Process）    —— 操作系统分配资源的最小单位，拥有独立的内存空间
  └── 线程（Thread） —— CPU 调度执行的最小单位，共享进程的内存空间
        └── 协程（Coroutine） —— 用户态轻量级"线程"，由程序自身调度，比线程更小
```

| 维度 | 进程 | 线程 | 协程 |
|------|------|------|------|
| 内存 | 独立空间，隔离性好 | 共享进程内存 | 共享线程内存 |
| 通信 | IPC（管道/队列/共享内存） | 直接访问共享变量（需加锁） | 直接访问，无需锁（单线程内切换） |
| 切换开销 | 大（内核态切换） | 中等（内核态切换） | 小（用户态切换） |
| 适用场景 | CPU 密集型 | IO 密集型 | 高并发 IO（网络请求等） |
| 并行能力 | 真正并行（多核） | 受 GIL 限制（CPython） | 并发而非并行 |

---

# GIL（全局解释器锁）

GIL（Global Interpreter Lock）是 **CPython** 解释器的一个机制：同一时刻，**只有一个线程能执行 Python 字节码**。

## 为什么存在

CPython 的内存管理（引用计数）不是线程安全的。GIL 是最简单的线程安全方案。没有 GIL 意味着需要为所有内置对象加细粒度锁，性能和复杂度都会显著上升。

> 其他 Python 实现（Jython、IronPython、PyPy）没有 GIL，但生态成熟度不如 CPython。

## 对并发的影响

- **CPU 密集型**：多线程**无效甚至更慢**（线程切换 + GIL 争抢），应使用**多进程**
- **IO 密集型**：多线程**有效**。当线程在等待 IO（网络、磁盘、sleep）时会释放 GIL，其他线程可以执行

```python
# 正确的选择原则：
# CPU 密集（计算、图像处理） → multiprocessing
# IO 密集（网络请求、文件读写） → threading 或 asyncio
```

# threading 多线程

适合**IO 密集型**任务。线程在等待 IO 时释放 GIL，其他线程可以推进。

```python
import threading
import time

def download(url):
    print(f"开始下载 {url}")
    time.sleep(2)                 # 模拟 IO 等待，此时 GIL 释放
    print(f"下载完成 {url}")

# 创建并启动线程
threads = []
for url in ["a.txt", "b.txt", "c.txt"]:
    t = threading.Thread(target=download, args=(url,))
    t.start()
    threads.append(t)

# 等待所有线程完成
for t in threads:
    t.join()

print("全部下载完成")
```

**线程安全**：多个线程共享内存，修改共享数据时需用 `Lock` 防止竞态条件：

```python
lock = threading.Lock()

def safe_update():
    with lock:                    # 获取锁，退出 with 块自动释放
        # 临界区代码
        shared_counter += 1
```

# multiprocessing 多进程

适合**CPU 密集型**任务。每个进程有独立的 Python 解释器和 GIL，可以真正利用多核 CPU。

```python
from multiprocessing import Process, Pool

def heavy_compute(n):
    """模拟 CPU 密集计算"""
    result = 0
    for i in range(n):
        result += i ** 2
    return result

# 进程池 —— 自动管理工作进程
with Pool(processes=4) as pool:
    results = pool.map(heavy_compute, [10**6, 10**6, 10**6, 10**6])
```

**与线程对比**：
- 进程间内存隔离，通信需要用 `Queue` 或 `Pipe` 传递数据（有序列化开销）
- 进程创建和切换的开销比线程大
- 适合真正的并行计算

# asyncio 异步 IO（略）

`asyncio` 是 Python 的异步编程框架，基于**事件循环（event loop）**。核心语法是 `async/await`：

```python
import asyncio

async def fetch(url):
    print(f"请求 {url}")
    await asyncio.sleep(1)        # 模拟异步 IO，await 时让出控制权
    print(f"完成 {url}")
    return f"结果-{url}"

async def main():
    # 并发发起多个请求
    results = await asyncio.gather(
        fetch("url1"),
        fetch("url2"),
        fetch("url3"),
    )
    print(results)

asyncio.run(main())
```

**协程**的关键特性：
- `async def` 定义的函数返回协程对象，不能直接调用，需 `await` 或放入事件循环
- `await` 会挂起当前协程，让事件循环执行其他协程，等结果就绪后再恢复
- 所有协程在**单个线程**中运行，没有 GIL 问题，也没有竞态条件
- 适合高并发 IO 场景（如 Web 服务器同时处理数千个连接）

# concurrent.futures（略）

`concurrent.futures` 模块提供了 `ThreadPoolExecutor` 和 `ProcessPoolExecutor`，用统一的接口管理线程池和进程池，让任务提交更简洁。
