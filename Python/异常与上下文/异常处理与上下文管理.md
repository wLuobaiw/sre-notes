
# try/except/else/finally

Python 的异常处理使用 `try/except/else/finally` 四段式结构：

| 子句 | 执行时机 |
|------|---------|
| `try` | 监控代码块，尝试执行 |
| `except` | 捕获特定异常类型并处理 |
| `else` | **未发生任何异常时**执行（放在 try 和 except 全部执行之后） |
| `finally` | **无论如何都执行**（常用于释放资源：关闭文件、释放锁等） |

```python
def read_config(path):
    try:
        with open(path, "r", encoding="utf-8") as f:
            data = f.read()
    except FileNotFoundError:
        print(f"文件 {path} 不存在")
        data = None
    except PermissionError:
        print(f"没有权限读取 {path}")
        data = None
    else:
        print("配置加载成功")      # 仅在无异常时执行
        data = data.strip()
    finally:
        print("读取操作结束")      # 无论是否异常都执行
    return data
```

**可捕获多个异常**：`except (TypeError, ValueError) as e:`。异常类有继承关系，捕获父类会同时捕获子类，通常从具体到通用排列。

# 常见内置异常

| 异常 | 触发条件 |
|------|---------|
| `ValueError` | 值类型正确但不合法（如 `int("abc")`、负数传入需要正数的函数） |
| `TypeError` | 类型不匹配（如对整数调用字符串方法、`"a" + 1`） |
| `KeyError` | **字典中访问不存在的键**（如 `d["missing_key"]`） |
| `IndexError` | 列表/元组索引越界 |
| `AttributeError` | 对象没有指定属性或方法 |
| `FileNotFoundError` | 文件不存在 |
| `ZeroDivisionError` | 除以零 |
| `ImportError` / `ModuleNotFoundError` | 导入模块失败 |
| `StopIteration` | 迭代器耗尽（通常由 `for` 循环自动捕获，无需手动处理） |

> `KeyError` 是键**不存在**时抛出的异常，与键的可哈希性无关。不可哈希的对象作为 key 会抛 `TypeError: unhashable type`。

# 自定义异常

继承 `Exception` 类即可创建自定义异常，用 `raise` 抛出：

```python
class ConfigError(Exception):
    """配置相关的异常"""
    def __init__(self, key, message="配置项无效"):
        self.key = key
        super().__init__(f"{message}: {key}")

# 使用
def get_config(d, key):
    if key not in d:
        raise ConfigError(key, "缺少必需配置项")
    return d[key]
```

按场景定义异常类型，能让调用方更精确地捕获和处理。

## raise from —— 异常链（略）

`raise ... from ...` 用于串联异常，保留原始异常信息，便于追踪根因。Python 3 中，在 `except` 块中抛出另一个异常时，默认会自动附加原异常信息。

# with 上下文管理器

`with` 语句确保资源在使用后被**自动释放**，无论中间是否发生异常。

```python
# 不用 with —— 需手动关闭
f = open("data.txt", "r")
try:
    content = f.read()
finally:
    f.close()               # 即使 try 中出错也会关闭

# 用 with —— 自动管理
with open("data.txt", "r") as f:
    content = f.read()      # 退出 with 块时自动关闭，无需 finally
```

`with` 不只用于文件，任何实现了 `__enter__` 和 `__exit__` 的对象（称为**上下文管理器**）都能配合 `with` 使用，如：

- 线程锁 `threading.Lock`
- 数据库连接与事务
- 临时修改环境或状态后自动恢复

`__enter__` 在进入 `with` 块时调用，`__exit__` 在退出时调用（接收异常信息）。

## contextlib（略）

`contextlib` 模块提供了 `@contextmanager` 装饰器，可以用生成器函数来创建上下文管理器，无需手动写 `__enter__`/`__exit__` 类。
