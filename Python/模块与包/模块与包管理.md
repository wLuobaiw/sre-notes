
# import 导入机制

## 基本导入方式

```python
import os                         # 导入整个模块
os.path.join("a", "b")            # 使用时需带模块名前缀

from os import path               # 导入模块中的指定名称
path.join("a", "b")               # 直接使用，无需前缀

from os import path as p          # 别名
p.join("a", "b")

from os import *                  # 导入全部（不推荐，容易污染命名空间）
```

`import xxx.yyy.zzz` 中，`xxx.yyy` 部分必须是包路径，最后一段 `zzz` 可以是模块或包内的子模块。

`from xxx.yyy import zzz` 中，`xxx.yyy` 是包路径，`zzz` 只能是一个模块名或具体名称，**不能带点号**。

## 相对导入（包内部使用）

在包的子模块中，可以用 `.` 表示当前包层级：

```python
from . import sibling_module      # 同目录的兄弟模块
from .. import parent_module      # 上级目录的模块
from .subpkg import child_module  # 子包中的模块
```

相对导入仅在包内部生效，**直接运行的脚本文件不能使用相对导入**。

# 包结构

一个目录要成为 Python 包，需要包含 `__init__.py` 文件（Python 3.3+ 可省略，但显式保留是更清晰的做法）。

```
my_package/
├── __init__.py          # 包的初始化文件，可为空
├── core.py
├── utils.py
└── sub_package/
    ├── __init__.py
    └── helper.py
```

`__init__.py` 的常见用途：
- 控制 `from package import *` 导出的内容（通过 `__all__` 列表）
- 在包被导入时执行初始化逻辑
- 将子模块的功能提升到包级别，方便用户使用

# pip 包管理

## 常用命令

| 命令 | 用途 |
|------|------|
| `pip install <pkg>` | 安装包 |
| `pip install <pkg>==1.0.0` | 安装指定版本 |
| `pip uninstall <pkg>` | 卸载包 |
| `pip list` | 列出已安装的包 |
| `pip show <pkg>` | 查看包详细信息 |
| `pip freeze > requirements.txt` | 导出当前环境所有包及版本 |
| `pip install -r requirements.txt` | 批量安装 requirements.txt 中列出的包 |

> `pip install -r`（`-r` = requirement），不是 `-f`。

## requirements.txt

项目根目录下的依赖清单文件，每行一个包名（可含版本约束）：

```
# requirements.txt
requests>=2.28.0
flask==3.0.0
numpy~=1.24.0     # ~= 表示兼容版本（>=1.24.0, <1.25.0）
```

常用于 Docker 镜像构建和项目部署中一键安装所有依赖。

# 虚拟环境（略）

虚拟环境是 Python 项目的**独立依赖空间**——让不同项目使用不同版本的同一个包而互不冲突。

核心工具 `venv`（Python 3.3+ 内置）：

```shell
python -m venv myenv           # 创建虚拟环境
source myenv/bin/activate      # Linux/Mac 激活
myenv\Scripts\activate         # Windows 激活
deactivate                     # 退出虚拟环境
```

**为什么需要虚拟环境**：

- 项目 A 需要 `requests==2.25.0`，项目 B 需要 `requests==2.31.0`——没有虚拟环境就无法同时满足
- 避免全局 Python 环境被污染，保持系统干净
- 确保部署环境与开发环境一致

其他工具：`virtualenv`（venv 的前身，功能类似）、`poetry`/`pipenv`（集成了依赖管理和虚拟环境，提供 lock 文件锁定版本）。
