# 1. 概念导入

哈希表（Hash Table）是一种通过 **键（Key）** 直接访问存储位置的数据结构。如果说数组是通过"第几个"来找数据，哈希表就是通过"叫什么名字"来找数据——就像电话簿里你不需要记住某人在第几页，只需要知道他的姓名就能找到号码。哈希表解决的核心问题是：如何用接近 O(1) 的时间完成数据的插入、删除和查找。

# 2. 核心原理

## 2.1 哈希函数：把键变成下标

哈希表的核心是一个 **哈希函数**，它接收一个键，返回一个整数（哈希值），再通过取模映射到数组的某个位置（桶）。

```
键 "张三"  ─→  哈希函数  ─→  整数 42817  ─→  42817 % 8 = 1  ─→  桶[1]
键 "李四"  ─→  哈希函数  ─→  整数 10932  ─→  10932 % 8 = 4  ─→  桶[4]
```

```python
# 模拟哈希表如何存数据
# 为什么用取模：哈希值通常很大，需要映射到有限的桶范围

def simple_hash(key: str, bucket_count: int) -> int:
    """一个简化的哈希函数：将每个字符的 ASCII 码相加后取模"""
    total = 0
    for char in key:
        total += ord(char)
    return total % bucket_count

print(simple_hash("张三", 8))  # 输出 1
print(simple_hash("李四", 8))  # 输出 4
```

## 2.2 哈希冲突：不可避免的问题

不同键可能得到相同的哈希值，这叫 **哈希冲突**。例如假设另一个键也映射到桶 1：

```
桶[1] 已经存了 "张三" → 信息
现在 "王五" 也要往桶[1] 存 → 冲突！
```

最常用的解决方法是 **拉链法（Separate Chaining）**：每个桶不直接存数据，而是存一个链表（或更高效的数据结构），冲突的键都挂在同一个桶的链表上。

```
哈希表数组：
┌─────┐
│  0  │  →  None
├─────┤
│  1  │  →  ("张三", info) → ("王五", info)  ← 链表解决冲突
├─────┤
│  2  │  →  None
├─────┤
│  3  │  →  ("赵六", info)
└─────┘
```

```python
# 用 Python dict 的实际表现来理解哈希表
d = {}

# 插入键值对 —— 内部调用哈希函数计算位置
d["张三"] = {"age": 25, "city": "北京"}
d["王五"] = {"age": 30, "city": "上海"}  # 可能冲突，但 dict 内部处理好了

# 查找 —— 一次哈希计算 + 链表查找（平均 O(1)）
# 为什么是 O(1)？因为链表长度通常很短（好的哈希函数均匀分布）
print(d["张三"])  # {'age': 25, 'city': '北京'}

# 删除 —— 同样是 O(1) 均摊
del d["王五"]
```

## 2.3 为什么 Python dict 的查找是 O(1)

dict 的底层实现做了多层优化：

1. **好的哈希函数**：Python 的字符串/整数哈希函数设计精密，尽量避免冲突。
2. **动态扩容**：当元素数量超过负载因子（约 2/3）时，自动扩大桶数组并重新哈希所有键。
3. **开放地址法**：Python 内部采用开放地址法（而非拉链法），冲突时按规则寻找下一个空位，避免链表指针开销。

```python
# 演示 dict 的哈希分布（用散列值观察）
keys = ["apple", "banana", "cherry", "date", "elderberry"]
for k in keys:
    # hash() 是 Python 内置哈希函数
    bucket = hash(k) % 8
    print(f"{k:10s} → hash={hash(k):12d} → 桶[{bucket}]")

# 输出示例（实际值每次运行可能不同）：
# apple      → hash=...  → 桶[?]
# banana     → hash=...  → 桶[?]
# ...
```

## 2.4 用 dict 实现简单的计数器

```python
# 统计列表中每个元素出现次数——哈希表的经典应用
# 为什么用 dict：需要按"元素值"快速查找和更新计数

nums = [1, 3, 2, 3, 1, 1, 5, 2, 3]
counter = {}

for num in nums:
    # dict.get(key, default)：如果键存在返回值，否则返回默认值
    # 为什么用 get 而非直接访问：避免键不存在时抛出 KeyError
    counter[num] = counter.get(num, 0) + 1

print(counter)  # {1: 3, 3: 3, 2: 2, 5: 1}

# Python 内置的 collections.Counter 就是基于这个原理
from collections import Counter
print(Counter(nums))  # Counter({1: 3, 3: 3, 2: 2, 5: 1})
```

# 3. 复杂度与适用场景

| 操作 | 平均时间复杂度 | 最坏时间复杂度 | 说明 |
|------|--------------|--------------|------|
| 插入 | **O(1)** | O(n) | 最坏情况所有键冲突到同一个桶 |
| 删除 | **O(1)** | O(n) | |
| 查找 | **O(1)** | O(n) | |
| 哈希计算 | O(k) | O(k) | k 为键的长度，通常可忽略 |
| 空间 | O(n) | O(n) | 实际会预留额外空间以降低冲突 |

**什么情况用哈希表：** 需要根据键快速查找/插入/删除、去重、计数、建立映射关系。
**什么情况不用：** 需要有序遍历（哈希表无序，可用 TreeMap 替代）、键的范围极小且连续时（数组更省空间）、需要按范围查找（如查所有年龄在 20-30 之间的用户）。

# 4. 常见变体

- **开放地址法（Open Addressing）**：冲突时寻找下一个空桶（线性探测、二次探测、双重哈希）。比拉链法省内存（无需指针），但删除操作更复杂（不能直接置空，需标记已删除）。Python 的 dict 和 set 底层采用开放地址法。
- **一致性哈希（Consistent Hashing）**：用于分布式缓存系统（如 Redis 集群），当桶数量变化时，只有少量键需要重新映射，避免大规模数据迁移。

# 5. 经典题目：两数之和（LeetCode 1）

## 题目描述
给定一个整数数组 `nums` 和一个目标值 `target`，找出数组中 **和为目标值** 的两个数的下标。假设每种输入只有一个解，不能重复使用同一个元素。

```
输入：nums = [2, 7, 11, 15], target = 9
输出：[0, 1]  （因为 nums[0] + nums[1] = 2 + 7 = 9）
```

## 思路分析
**哈希表一次遍历**：遍历数组时，将每个元素的值和下标存入哈希表。对于当前元素 `nums[i]`，检查 `target - nums[i]` 是否已经在哈希表中——如果在，就找到了答案。

```
为什么一次遍历就够了？
当遍历到 nums[i] 时，哈希表中存的是之前遍历过的所有元素。
如果之前出现过 complement = target - nums[i]，就直接返回。
如果没出现过，把当前元素加入哈希表，供后面的元素匹配。

遍历过程：
  i=0, nums[0]=2, complement=9-2=7, 哈希表为空 → 存入 {2:0}
  i=1, nums[1]=7, complement=9-7=2, 哈希表中有 2 → 返回 [0,1]
```

## 完整代码

```python
def two_sum(nums: list[int], target: int) -> list[int]:
    """
    用哈希表一次遍历找出两数之和。
    为什么用哈希表：需要在 O(1) 时间内判断 complement 是否出现过，
    如果不用哈希表，每次都要遍历已访问元素，总复杂度退化为 O(n²)。
    """
    # key: 元素值, value: 元素下标
    # 为什么存下标：题目要求返回下标，不是元素值
    seen = {}

    for i, num in enumerate(nums):
        complement = target - num
        # complement 在哈希表中意味着已经出现过
        if complement in seen:
            # 注意顺序：seen[complement] 在前（先出现的），i 在后
            return [seen[complement], i]
        # 为什么在返回后才存：避免同一个元素被用两次
        # 例如 target=6, num=3 时，complement=3，如果先存入会返回 [i, i]
        seen[num] = i

    # 题目保证有解，理论上不会走到这里
    return []


# 测试
test_nums = [2, 7, 11, 15]
test_target = 9
result = two_sum(test_nums, test_target)
print(f"nums={test_nums}, target={test_target} → {result}")
# 输出：nums=[2, 7, 11, 15], target=9 → [0, 1]

# 更多测试用例
test_cases = [
    ([3, 2, 4], 6, [1, 2]),         # 3+2=5不对，2+4=6
    ([3, 3], 6, [0, 1]),            # 相同元素但不同下标
    ([1, 5, 3, 6], 9, [1, 3]),      # 5+6=9
]

for nums, target, expected in test_cases:
    result = two_sum(nums, target)
    status = "✓" if result == expected else "✗"
    print(f'{status} nums={nums}, target={target} → {result}（期望 {expected}）')
```
