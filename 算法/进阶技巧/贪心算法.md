# 1. 概念导入

去超市买水果，你手上是最大号的袋子——你自然会把最大的水果先装进去，再装次大的，直到袋子装满。**贪心算法就是每一步都做"当前看起来最好"的选择，并且绝不回头、不后悔。** 但注意：并不是所有问题都能这样"鼠目寸光"地解决——只有当局部最优能推导出全局最优时，贪心才有效。

# 2. 核心原理

## 2.1 什么是贪心选择

贪心不做全局规划，只看眼前：从当前状态的所有选项中，选一个"看起来最好"的，然后进入下一个状态。

**举例：找零问题**。假设硬币面额为 [25, 10, 5, 1]（美分），要找 63 美分。贪心策略：每次都选不超过剩余金额的最大面额。

```python
def greedy_change(amount, coins=[25, 10, 5, 1]):
    """贪心找零：每次选能用的最大面额"""
    coins.sort(reverse=True)       # 从大到小排序
    result = []
    for coin in coins:
        while amount >= coin:
            amount -= coin         # 为什么用 while？可能要用多个同面额
            result.append(coin)
    return result


print(greedy_change(63))
# 输出: [25, 25, 10, 1, 1, 1]
```

这种面额体系下贪心是最优的，但如果面额是 [1, 3, 4]，要找 6 分，贪心会选 [4, 1, 1]（3 枚），而最优解是 [3, 3]（2 枚）——贪心失败了。**贪心正确的前提是问题具有贪心选择性质。**

## 2.2 贪心适用的两个条件

- **贪心选择性质**：全局最优解可以通过一系列局部最优选择来达到。换句话说，选了这一步之后，剩下的问题仍然是同类子问题，且子问题的最优解和这一步组合就是全局最优。
- **最优子结构**：问题的最优解包含子问题的最优解（这一点和 DP 相同）。

## 2.3 找零贪心的代码演示

对比上面的 [1, 3, 4] 面额，验证贪心有时不成立：

```python
def is_greedy_optimal(amount, coins):
    """
    验证贪心是否失败 —— 用枚举找最优解作为对比
    为什么需要这个函数？帮助理解贪心不是万能的
    """
    coins.sort(reverse=True)
    greedy_result = 0
    remaining = amount
    for c in coins:
        cnt = remaining // c
        greedy_result += cnt
        remaining -= cnt * c

    # DP 求真正的最优解（最小硬币数）
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for c in coins:
            if i >= c:
                dp[i] = min(dp[i], dp[i - c] + 1)
    return greedy_result == dp[amount], greedy_result, dp[amount]


print(is_greedy_optimal(6, [1, 3, 4]))
# 输出: (False, 3, 2)  贪心 3 枚，最优 2 枚
```

## 2.4 贪心 vs 动态规划

贪心和 DP 都依赖最优子结构，但核心区别在于：

| | 贪心 | DP |
|--|------|----|
| 决策方式 | 选当前最优，不回头 | 枚举所有可能，选整体最优 |
| 子问题依赖 | 选完之后只剩一个子问题 | 多个子问题都需要考虑 |
| 典型代表 | 找零、区间调度 | 背包、编辑距离 |

**简单判断：如果某步选择后会缩小问题规模且不影响剩余选择的独立性，通常可以贪心。**

# 3. 复杂度与适用场景

| 维度 | 说明 |
|------|------|
| 时间复杂度 | 通常 O(n log n) —— 排序是贪心的常见前置操作 |
| 空间复杂度 | O(1)（不含排序栈空间） |
| 适用场景 | 局部最优 = 全局最优的问题（区间调度、最小生成树、哈夫曼编码） |
| 不适用场景 | 需要全局权衡的问题（背包问题、旅行商） |

# 4. 常见变体

- **区间调度**：选择最多互不重叠的区间。按结束时间排序，每次选结束最早且不与已选重叠的区间——经典贪心。
- **哈夫曼编码**：数据压缩算法。每次合并频率最小的两个节点，构造最优前缀码。

# 5. 经典题目：LeetCode 455 —— 分发饼干

**题目描述**：每个孩子有一个胃口值 g[i]，每个饼干有一个尺寸 s[j]。每个孩子最多给一块饼干，且饼干尺寸 >= 孩子胃口时孩子才能满足。问最多能满足多少个孩子？

**思路分析**：贪心策略——最小尺寸的饼干优先分给胃口最小的孩子。排序后双指针，g 和 s 各遍历一次。

```python
def find_content_children(g: list[int], s: list[int]) -> int:
    """
    贪心：把最小的饼干给最小胃口的孩子
    为什么排序？不排序无法"最小配最小"，需要有序才能做贪心比较
    """
    g.sort()
    s.sort()
    child = 0          # 指向当前考虑的孩子（已满足的索引）
    cookie = 0         # 指向当前考虑的饼干

    while child < len(g) and cookie < len(s):
        if s[cookie] >= g[child]:
            child += 1   # 满足了这个孩子
        # 为什么不满足也要 cookie += 1？
        # 因为饼干尺寸有序，当前饼干不够，更大的饼干才有机会
        cookie += 1

    return child


if __name__ == "__main__":
    print(find_content_children([1, 2, 3], [1, 1]))    # 输出: 1
    print(find_content_children([1, 2], [1, 2, 3]))    # 输出: 2
    print(find_content_children([10, 9, 8], [5, 6, 7]))  # 输出: 0
```

时间复杂度 O(n log n + m log m)（排序），空间复杂度 O(1)（原地排序）。贪心保证了在"当前最小饼干能满足当前最小胃口"时立即分配，不会浪费大的饼干在小的胃口上。
