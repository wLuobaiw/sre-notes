# 1. 概念导入

想象你在走一个巨大的迷宫，每遇到岔路口就选一条路走，如果走到死胡同就退回到上一个岔路口，换另一条路继续走。**回溯算法就是系统地枚举所有可能解，但在发现当前路径不可能通向有效解时及时"回头"（撤销选择）。** 它本质上是带"剪枝"的深度优先搜索，常用于排列、组合、子集等问题。

# 2. 核心原理

## 2.1 回溯三要素

任何一个回溯问题都可以抽象为三个东西：

- **路径**：已经做出的选择（当前已走过的路）。
- **选择列表**：当前可以做的选择（面前的岔路）。
- **终止条件**：什么时候说明这条路走完了（到了迷宫出口或死胡同）。

## 2.2 决策树 —— 选/不选的分支

以集合 `[1, 2]` 的子集问题为例，每个元素"选或不选"形成一棵二叉决策树：

```
                []
              /    \
           [1]      []
          /   \    /   \
       [1,2] [1] [2]   []
```

叶子节点就是所有子集：{[1,2], [1], [2], []}。回溯就是深度优先遍历这棵树，每到一个叶子就记录结果。

## 2.3 回溯标准模板

```python
def backtrack(路径, 选择列表):
    if 满足终止条件:
        结果.append(路径的副本)   # 为什么副本？路径会变，不复制会引用同一对象
        return
    
    for 选择 in 选择列表:
        # 做选择
        路径.append(选择)
        # 进入下一层决策树
        backtrack(新路径, 新选择列表)
        # 撤销选择（回溯的核心操作）
        路径.pop()
```

"撤销选择"这一行是回溯的灵魂——它让程序能回到岔路口，尝试另一条路。没有这一步，路径就回不去了。

## 2.4 剪枝优化

回溯的缺点是复杂度高（通常是 O(2^n) 或 O(n!)），但如果提前知道某条分支不可能产生有效解，可以提前终止——这就是**剪枝**。

```python
# 剪枝示例：组合求和问题中，如果当前路径和已经超过目标值
# 为什么剪枝？dfs 中剪枝可以省掉整个子树的遍历
def backtrack_with_prune(路径, 剩余目标):
    if 剩余目标 < 0:
        return  # 剪枝：这条路已经超了，不用再走
    if 剩余目标 == 0:
        结果.append(路径[:])  # 到达叶子：找到了一个有效解
        return
    for 选择 in 选择列表:
        路径.append(选择)
        backtrack_with_prune(路径, 剩余目标 - 选择)
        路径.pop()
```

# 3. 复杂度与适用场景

| 维度 | 说明 |
|------|------|
| 时间复杂度 | 通常 O(2^n) 或 O(n!)，剪枝后可能大幅降低 |
| 空间复杂度 | O(n)（递归栈深度 + 路径存储） |
| 适用场景 | 全排列、子集、组合、N 皇后、数独等"列举所有可能"的问题 |
| 不适用场景 | 问题规模太大（n>20 左右）、存在更优的数学解、只需要计数而非枚举 |

# 4. 常见变体

- **全排列**：每个位置尝试所有未被选过的数字。选择列表会随路径动态缩小。
- **N 皇后**：逐行放置皇后，每列、每对角线检查是否冲突。用三个集合（列、主对角线、副对角线）做 O(1) 冲突判断。
- **组合总和**：从数组中选若干数使其和为目标值。常搭配排序 + 剪枝来去重。

# 5. 经典题目：LeetCode 78 —— 子集

**题目描述**：给定一个不含重复元素的整数数组 nums，返回该数组所有可能的子集（幂集）。

**思路分析**：每个元素「选或不选」，用回溯模板遍历决策树。选择列表是当前元素之后的所有元素（避免重复），终止条件是到达数组末尾。

```python
def subsets(nums: list[int]) -> list[list[int]]:
    """回溯标准模板求所有子集"""
    res = []
    path = []          # 记录当前路径（已选元素）

    def backtrack(start):
        """
        为什么需要 start 参数？
        保证每次只选 start 之后的元素，避免产生 [1,2] 和 [2,1] 这种重复
        """
        # 为什么每次递归都要加入结果？
        # path 的每个状态都是一个合法的子集，不仅仅是叶子节点
        res.append(path[:])

        for i in range(start, len(nums)):
            # 做选择：把 nums[i] 加入当前子集
            path.append(nums[i])
            # 进入下一层：下一个元素的起始是 i+1
            backtrack(i + 1)
            # 撤销选择：回溯的核心，回到之前的状态
            path.pop()

    backtrack(0)
    return res


if __name__ == "__main__":
    nums = [1, 2, 3]
    result = subsets(nums)
    print(f"nums={nums} 的子集:")
    for s in sorted(result, key=lambda x: (len(x), x)):
        print(s)
    """
    输出:
    nums=[1, 2, 3] 的子集:
    []
    [1]
    [2]
    [3]
    [1, 2]
    [1, 3]
    [2, 3]
    [1, 2, 3]
    """
```

这段代码的关键在于：每次递归时都把当前 path 加入结果（而不是只在叶子节点才加入），这样所有中间状态也被记录为子集。`path.pop()` 是最核心的一行——没有它，路径只增不减，程序会沿着一条路走到黑，永远回不到岔路口。
