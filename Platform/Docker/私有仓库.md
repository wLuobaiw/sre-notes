# 为什么需要私有仓库

Docker 官方仓库 Docker Hub 是公开的，而企业内部需要安全的、可控的镜像存储与分发。

| 需求 | 说明 |
|:-----|:-----|
| **安全隔离** | 企业代码构建的镜像不应暴露在公网 |
| **网络效率** | 内网拉取速度远快于外网，大镜像可达数倍差距 |
| **合规要求** | 金融、政务等行业要求数据不出机房 |
| **镜像审计** | 需要知道谁推送了什么、什么时候推送的 |
| **漏洞管控** | 必须扫描镜像中的 CVE 漏洞，阻断高危镜像上线 |

# Docker Distribution（官方 Registry）

Docker 官方提供了最基础的镜像仓库实现——Distribution（原名 Docker Registry），纯 Go 编写，无外部依赖。

```shell
# 极简启动
docker run -d -p 5000:5000 --name registry registry:2
```

```shell
# 推送镜像到私有仓库
docker tag myapp:latest localhost:5000/myapp:latest
docker push localhost:5000/myapp:latest
```

**核心缺陷**：

- 没有 Web UI，全靠 API 操作
- 没有用户认证和权限控制
- 没有镜像扫描
- 没有镜像复制/同步
- 没有垃圾回收（GC）界面

> 官方 Registry 适合本地开发测试，生产环境推荐使用 Harbor。

# Harbor —— 企业级私有仓库

[Harbor](https://github.com/goharbor/harbor) 是 CNCF 毕业项目，在官方 Registry 之上增加了**认证授权、漏洞扫描、镜像复制、策略管理、Web UI** 等企业级功能，是目前事实上的企业私有仓库标准。

## 部署方式

**Docker Compose 部署**（适合中小规模）：

```shell
# 1. 下载 Harbor 离线安装包
wget https://github.com/goharbor/harbor/releases/download/v2.10.0/harbor-offline-installer-v2.10.0.tgz
tar xvf harbor-offline-installer-v2.10.0.tgz

# 2. 复制并编辑配置文件
cd harbor
cp harbor.yml.tmpl harbor.yml
vim harbor.yml    # 配置 hostname、https(证书)、admin密码、存储路径

# 3. 安装
./install.sh --with-trivy    # 同时安装漏洞扫描模块
```

**Helm 部署**（Kubernetes 环境）：

```shell
helm repo add harbor https://helm.goharbor.io
helm install harbor harbor/harbor \
  --set expose.type=nodePort \
  --set harborAdminPassword=Harbor12345
```

## 项目（Project）管理

Harbor 以**项目**为单位组织镜像，每个项目有独立的：
- **成员与角色**（项目管理员、维护者、开发者、访客）
- **访问级别**（公开 / 私有）
- **存储配额**
- **镜像不可变规则**：设置后同名 tag 不可覆盖，防止生产镜像被意外替换
- **内容信任**：仅允许推送经过 Notary 签名的镜像

```shell
# CLI 创建项目
curl -X POST "https://harbor.example.com/api/v2.0/projects" \
  -H "Authorization: Basic <base64_token>" \
  -d '{"project_name":"backend","public":false}'
```

## 镜像复制（Replication）

Harbor 支持在多个实例之间自动同步镜像，典型场景：

| 场景 | 说明 |
|:-----|:-----|
| **多数据中心** | 总部 Harbor → 各地机房 Harbor，就近拉取 |
| **混合云** | 私有 Harbor ↔ 云上 Harbor（ACR/ECR） |
| **灾备** | 主 Harbor → 备 Harbor，主故障时切到备 |
| **内外网隔离** | 外网 Harbor 拉 Docker Hub → 同步到内网 Harbor |

复制策略支持：
- **Push 模式**：本 Harbor 推送镜像到远程仓库
- **Pull 模式**：本 Harbor 从远程仓库拉取镜像
- **过滤规则**：按仓库名、tag、标签等过滤
- **触发方式**：手动、定时、事件驱动（有推送时自动同步）

## 代理缓存（Proxy Cache）

Harbor 可以配置为 Docker Hub 等上游仓库的**代理缓存**，将外网镜像自动缓存到本地：

```
开发者拉取 harbor.internal/proxy_cache/nginx:latest
       │
       ▼
  Harbor（代理缓存项目）
       │
       ├─ 本地有缓存 → 直接返回（内网速度）
       │
       └─ 本地无缓存 → 从 Docker Hub 拉取 → 缓存 → 返回
```

优势：
- 内网拉取速度极大提升
- 减少外网带宽消耗
- 避免 Docker Hub 速率限制（匿名用户 6小时/100次 pull）
- 对开发者透明，只需改镜像地址前缀

## 漏洞扫描

Harbor 集成 Trivy（默认）或 Clair 作为漏洞扫描器：

- **自动扫描**：镜像推送到 Harbor 后自动触发扫描
- **阻拦策略**：高危漏洞数量超过阈值时阻止镜像拉取
- **定时全量扫描**：CVE 数据库更新后重新扫描已有镜像

```yaml
# harbor.yml 中的扫描配置
trivy:
  ignore_unfixed: false       # 是否忽略没有修复版本的漏洞
  skip_update: false          # 是否跳过 CVE 数据库更新
  offline_scan: false         # 离线扫描模式（使用本地 CVE 数据）
```

## 垃圾回收（GC）

删除镜像或 tag 后，底层存储并不会立即释放。需要执行垃圾回收：

```shell
# Harbor 默认注册为 systemd 服务时
docker exec registry /bin/registry garbage-collect /etc/registry/config.yml
```

**重要**：GC 期间 Harbor 会设为只读模式，建议在维护窗口执行。

# 登录与推送

```shell
# 登录 Harbor
docker login harbor.example.com -u admin -p Harbor12345

# 打标签
docker tag myapp:latest harbor.example.com/backend/myapp:v1.0.0

# 推送
docker push harbor.example.com/backend/myapp:v1.0.0

# 拉取
docker pull harbor.example.com/backend/myapp:v1.0.0
```

# 在生产环境配置 HTTPS

自签名证书或 Let's Encrypt 证书配置在 `harbor.yml` 的 `https` 段：

```yaml
# harbor.yml
hostname: harbor.example.com
https:
  port: 443
  certificate: /etc/harbor/certs/harbor.crt
  private_key: /etc/harbor/certs/harbor.key
```

每个需要访问 Harbor 的 Docker 客户端必须信任该证书：

```shell
# 将证书复制到 Docker 的证书目录
mkdir -p /etc/docker/certs.d/harbor.example.com
cp harbor.crt /etc/docker/certs.d/harbor.example.com/
systemctl restart docker
```

# 方案对比

| 特性 | Harbor | Docker Distribution | 云厂商（ACR/ECR） |
|:-----|:------|:--------------------|:-------------------|
| 开源/免费 | 是 | 是 | 否（按存储收费） |
| Web UI | 完善 | 无 | 控制台集成 |
| 漏洞扫描 | 内置 Trivy | 无 | 通常内置 |
| 镜像复制 | 完善的策略引擎 | 无 | 通常支持 |
| RBAC | 项目级细粒度 | 无 | 通常支持 |
| 代理缓存 | 支持 | 需手动配置 | 部分支持 |
| 高可用 | 需自行搭建 | 需自行搭建 | 云平台保障 |

# 运维要点

1. **定期执行垃圾回收**：防止存储空间膨胀，建议每月一次或在保留策略清理后执行
2. **配置镜像保留策略**：按镜像数量或时间自动清理旧版本，避免磁盘无限增长
3. **CVE 数据库保持更新**：漏洞扫描的准确性依赖于最新的 CVE 数据
4. **配置镜像不可变性**：生产环境的关键镜像应禁止同名 tag 覆盖
5. **开启 HTTPS**：绝不使用 HTTP 访问 Harbor，镜像传输不加密等同于明文传输
6. **备份 PostgreSQL 数据库**：Harbor 所有元数据（项目、用户、策略）存储在 PG 中
