# 日志机制

Docker 默认将容器内进程的 **stdout（标准输出）** 和 **stderr（标准错误）** 通过**日志驱动（Logging Driver）** 收集并转发。理解这一机制是生产环境中日志管理的基础。

## 核心原理

```
┌─────────────┐
│ 容器内进程    │
│ stdout/stderr│
└──────┬──────┘
       │ 容器运行时收集
       ▼
┌─────────────┐
│ Logging     │  ← 日志驱动层（可插拔）
│ Driver      │
└──────┬──────┘
       │ 转发到目标
       ▼
┌──────────────────────────────┐
│ 宿主机文件 / syslog /         │
│ fluentd / Loki / ELK ...     │
└──────────────────────────────┘
```

容器内应用只需向 stdout 输出日志即可，无需关心日志最终去往何处——这是 Docker 日志驱动的职责。

## 查看当前日志驱动

```shell
docker info --format '{{.LoggingDriver}}'    # 默认通常是 json-file
```

# 日志驱动详解

| 驱动 | 存储位置 | 特点 | 适用场景 |
|:-----|:---------|:-----|:---------|
| `json-file` | 宿主机 `/var/lib/docker/containers/<id>/<id>-json.log` | Docker 默认驱动，JSON 格式，支持 `docker logs` | 开发环境、单机部署 |
| `local` | 宿主机 `/var/lib/docker/containers/<id>/local-logs/` | 比 json-file 更省空间，自动轮转，但 `docker logs` 功能受限 | 生产环境单机场景 |
| `syslog` | 系统 syslog | 写入系统 syslog 服务 | 传统运维环境 |
| `journald` | systemd journal | 写入 systemd journal | systemd 管理的宿主机 |
| `fluentd` | 发送到 fluentd 服务 | 通过网络发送到 fluentd 聚合器 | 集中式日志收集 |
| `gelf` | 发送到 Graylog | GELF 格式发送到 Graylog | 使用 Graylog 的团队 |
| `loki` | 发送到 Grafana Loki | 通过 loki-docker-driver 插件 | 使用 Loki + Grafana 的团队 |
| `splunk` | 发送到 Splunk | 企业级日志平台 | 使用 Splunk 的组织 |
| `none` | 不收集 | 禁用日志收集 | 不关心日志的临时容器 |

> **关键区别**：`json-file` 和 `local` 将日志写入宿主机文件，`docker logs` 可以回读；而 `fluentd`、`gelf`、`loki` 等远程驱动将日志**发送到外部系统**，`docker logs` 无法看到历史日志。

# json-file 驱动配置

## 默认行为的问题

`json-file` 驱动默认**不限制日志文件大小、不轮转**，容器长时间运行可能导致日志文件占满宿主机磁盘。

## 按容器配置日志轮转

```shell
docker run -d \
  --log-driver json-file \
  --log-opt max-size=10m \      # 单个日志文件最大 10MB
  --log-opt max-file=3 \         # 最多保留 3 个轮转文件
  --log-opt labels=env \         # 日志中包含哪些 label
  nginx:latest
```

## 全局默认配置（daemon.json）

在 `/etc/docker/daemon.json` 中设置全局默认值：

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3",
    "labels": "production_status",
    "env": "os"
  }
}
```

修改后需重启 Docker：`systemctl restart docker`。

> 全局配置只对新创建的容器生效，已有容器不受影响。

# docker logs 命令进阶

```shell
# 查看最后 100 行
docker logs --tail 100 <容器>

# 实时跟踪（类似 tail -f）
docker logs -f <容器>

# 显示时间戳
docker logs -t <容器>

# 只看某时间段内的日志
docker logs --since 2026-06-01T00:00:00 --until 2026-06-02T00:00:00 <容器>
```

**注意**：`docker logs` 只能读取 json-file 或 journald 驱动下的日志。如果用了 fluentd/loki/splunk，需要用对应平台的查询工具。

# 集中式日志方案

单机上的日志文件只是过渡方案。生产环境中，需要将多台宿主机上所有容器的日志汇聚到一个中央平台。

## EFK 方案（Elasticsearch + Fluentd + Kibana）

```yaml
# docker-compose.yml 示例：用 fluentd 收集日志
services:
  app:
    image: myapp:latest
    logging:
      driver: fluentd
      options:
        fluentd-address: "fluentd:24224"
        tag: "docker.{{.Name}}"       # 用容器名作为日志标签

  fluentd:
    image: fluent/fluentd:v1.16
    volumes:
      - ./fluent.conf:/fluentd/etc/fluent.conf
    ports:
      - "24224:24224"

  elasticsearch:
    image: elasticsearch:8.10.0
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false

  kibana:
    image: kibana:8.10.0
    ports:
      - "5601:5601"
    environment:
      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
```

## Loki + Grafana 方案（轻量替代）

Loki 设计理念与 ELK 不同：**不对日志做全文索引**，只索引标签（label），日志正文以块存储。这使得 Loki 资源占用远低于 Elasticsearch。

```yaml
# docker-compose.yml 示例：用 loki 收集日志
services:
  app:
    image: myapp:latest
    logging:
      driver: loki
      options:
        loki-url: "http://loki:3100/loki/api/v1/push"
        loki-external-labels: "job=docker,env=production"

  loki:
    image: grafana/loki:2.9
    ports:
      - "3100:3100"

  grafana:
    image: grafana/grafana:10.2
    ports:
      - "3000:3000"
```

安装 Loki 日志驱动：`docker plugin install grafana/loki-docker-driver:latest --alias loki --grant-all-permissions`

## 选型对比

| 维度 | EFK 方案 | Loki 方案 |
|:-----|:---------|:----------|
| 日志索引方式 | 全文索引 | 仅索引标签 |
| 资源消耗 | 高（内存/CPU） | 低 |
| 查询速度 | 快（全文搜索） | 取决于标签设计 |
| 运维复杂度 | 高 | 较低 |
| 适合日志量 | 中等 | 非常大 |
| 与 K8s 集成 | 传统方案 | 原生集成（Grafana 生态） |

# 应用日志最佳实践

## 输出到 stdout/stderr

```dockerfile
# 好：应用直接写 stdout
CMD ["nginx", "-g", "daemon off;"]

# 差：写入容器内文件，日志困在容器中无法被 Docker 引擎收集
CMD nginx && tail -f /var/log/nginx/access.log
```

如果应用框架强制写文件，可以用符号链接把日志文件重定向到 stdout：

```dockerfile
RUN ln -sf /dev/stdout /var/log/nginx/access.log && \
    ln -sf /dev/stderr /var/log/nginx/error.log
```

## 结构化日志

使用 JSON 格式输出日志，便于下游日志平台解析和查询：

```
# 非结构化（难以查询）
2026-06-03 15:30:22 User bob Login Success from 10.0.1.5

# 结构化（可按字段过滤）
{"time":"2026-06-03T15:30:22Z","user":"bob","action":"login","result":"success","ip":"10.0.1.5"}
```

## 避免敏感信息泄漏

日志中不应包含密码、Token、身份证号等敏感数据。在应用代码层面做脱敏，或在日志平台做过滤。
