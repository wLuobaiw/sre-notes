# 内置工具

## docker stats

最快速的实时资源使用情况查看：

```shell
docker stats                    # 所有运行中的容器
docker stats <容器名> <容器名>  # 指定容器
```

输出每容器的 CPU%、内存使用/限制、网络 I/O、磁盘 I/O、PID 数。默认**持续输出**，`--no-stream` 只输出一次。数据来自 cgroup，精度不如专用监控工具。

## docker system df

查看 Docker 整体磁盘占用：

```shell
docker system df                # 总览
docker system df -v             # 每个镜像/容器/卷的详细信息
```

输出分类：

| 类型 | 说明 |
|:-----|:-----|
| Images | 所有镜像的总大小 + 可回收空间（悬空镜像） |
| Containers | 所有容器的可写层总大小 |
| Local Volumes | 命名卷和数据卷总大小 |
| Build Cache | BuildKit 构建缓存 |

```shell
# 一键清理未使用的镜像、容器、卷、网络
docker system prune -a --volumes
```

## docker events

实时监听 Docker Daemon 的事件流，用于追踪容器生命周期变化：

```shell
docker events                    # 实时监听
docker events --since 1h         # 最近1小时内的事件
docker events --filter type=container --filter event=die
```

事件类型包括 `container`（create/start/stop/die）、`image`（pull/push/delete）、`volume`、`network` 等。适合与告警系统集成。

# cAdvisor（Container Advisor）

Google 开源的容器资源监控工具，专门为容器环境设计，原生支持 Docker。

## 核心能力

- 自动发现宿主机上所有容器
- 采集 CPU、内存、网络、磁盘的细粒度指标
- 提供 Prometheus 格式的 metrics 端点
- 内置简易 Web UI

## 部署

```shell
docker run -d \
  --name=cadvisor \
  --volume=/:/rootfs:ro \
  --volume=/var/run:/var/run:ro \
  --volume=/sys:/sys:ro \
  --volume=/var/lib/docker/:/var/lib/docker:ro \
  --volume=/dev/disk/:/dev/disk:ro \
  --publish=8080:8080 \
  --privileged \
  --device=/dev/kmsg \
  gcr.io/cadvisor/cadvisor:latest
```

浏览器访问 `http://<宿主机IP>:8080` 即可看到所有容器的实时资源图表。

## 暴露的指标

cAdvisor 在 `:8080/metrics` 暴露 Prometheus 格式的指标，主要包括：

| 指标分类 | 示例指标 | 说明 |
|:---------|:---------|:-----|
| CPU | `container_cpu_usage_seconds_total` | 累计 CPU 使用时间 |
| 内存 | `container_memory_working_set_bytes` | 工作集内存（实际使用） |
| 网络 | `container_network_receive_bytes_total` | 累计网络接收字节 |
| 磁盘 I/O | `container_fs_writes_bytes_total` | 累计磁盘写入字节 |
| 文件系统 | `container_fs_usage_bytes` | 文件系统使用量 |

# Prometheus + Grafana 集成

cAdvisor 只是数据采集层，生产环境需要与 Prometheus（存储+查询）和 Grafana（可视化）组合：

```
┌───────────┐    ┌───────────┐    ┌───────────┐
│ 宿主机 1   │    │ 宿主机 2   │    │ 宿主机 N   │
│ ┌───────┐ │    │ ┌───────┐ │    │ ┌───────┐ │
│ │cAdvisor│ │    │ │cAdvisor│ │    │ │cAdvisor│ │
│ └───┬───┘ │    │ └───┬───┘ │    │ └───┬───┘ │
└─────┼─────┘    └─────┼─────┘    └─────┼─────┘
      │                │                │
      └────────────────┼────────────────┘
                       │ /metrics (pull)
                       ▼
              ┌────────────────┐
              │   Prometheus   │  ← 时序数据库，定期抓取
              └───────┬────────┘
                      │
                      ▼
              ┌────────────────┐
              │    Grafana     │  ← 仪表盘、告警
              └────────────────┘
```

## docker-compose 快速搭建

```yaml
version: '3.8'

services:
  cadvisor:
    image: gcr.io/cadvisor/cadvisor:latest
    volumes:
      - /:/rootfs:ro
      - /var/run:/var/run:ro
      - /sys:/sys:ro
      - /var/lib/docker/:/var/lib/docker:ro
    privileged: true
    devices:
      - /dev/kmsg

  prometheus:
    image: prom/prometheus:latest
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
      - prometheus_data:/prometheus
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.retention.time=30d'   # 保留30天数据
    ports:
      - "9090:9090"

  grafana:
    image: grafana/grafana:latest
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin
    volumes:
      - grafana_data:/var/lib/grafana
    ports:
      - "3000:3000"

volumes:
  prometheus_data:
  grafana_data:
```

**Prometheus 配置**（`prometheus.yml`）：

```yaml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: 'cadvisor'
    static_configs:
      - targets: ['cadvisor:8080']
```

# 健康检查

## Dockerfile HEALTHCHECK

健康检查用于让 Docker 知道容器内的应用是否真正"活着"，而不仅仅是主进程在运行。

```dockerfile
# 基础用法：curl 应用健康端点
HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD curl -f http://localhost:8080/health || exit 1

# 验证数据库是否可连接
HEALTHCHECK --interval=10s --timeout=3s --retries=5 \
  CMD mysqladmin ping -h localhost -u root -p${MYSQL_ROOT_PASSWORD} || exit 1

# 基于文件存在的简单检查
HEALTHCHECK --interval=1m --timeout=10s \
  CMD test -f /tmp/app-ready || exit 1
```

**参数说明**：

| 参数 | 默认值 | 说明 |
|:-----|:-------|:-----|
| `--interval` | 30s | 检查间隔 |
| `--timeout` | 30s | 单次检查超时 |
| `--start-period` | 0s | 启动宽限期（期间失败不计入重试） |
| `--start-interval` | 5s | 启动期内的检查间隔（Docker 25+） |
| `--retries` | 3 | 连续失败 N 次后标记为 unhealthy |

## 健康状态

容器在 `docker ps` 的 STATUS 列会显示：

```
STATUS
Up 10 seconds (health: starting)   # 启动宽限期内
Up 2 minutes (healthy)             # 正常
Up 5 minutes (unhealthy)           # 健康检查失败
```

## Docker Compose 中的健康检查与依赖

```yaml
services:
  app:
    image: myapp:latest
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 15s
      timeout: 3s
      retries: 3
      start_period: 10s
    depends_on:
      db:
        condition: service_healthy    # 等 db 变成 healthy 后启动

  db:
    image: postgres:15-alpine
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d mydb"]
      interval: 5s
      timeout: 3s
      retries: 5
```

>`depends_on` + `condition: service_healthy` 比单纯的依赖名更强：不仅保证启动顺序，还保证被依赖的服务已经就绪可用。

## 设计原则

1. **检查的是应用能力，不是进程存活**：进程可能活着但死锁/挂起，`curl /health` 比 `ps` 更有效
2. **健康端点应轻量**：不要触发复杂的数据库查询或外部 API 调用
3. **区分就绪和存活**：启动中未就绪（不应被杀掉）vs 已就绪后异常（应该重启）
4. **`--start-period` 给足启动时间**：数据库等大型应用启动可能需要数十秒，避免误判

# 告警规则示例

在 Prometheus 中配置的常见告警规则：

```yaml
groups:
  - name: docker_alerts
    rules:
      - alert: ContainerHighCPU
        expr: rate(container_cpu_usage_seconds_total[5m]) > 0.9
        for: 10m
        annotations:
          summary: "容器 {{ $labels.name }} CPU 使用率超过 90%，持续 10 分钟"

      - alert: ContainerHighMemory
        expr: container_memory_usage_bytes / container_spec_memory_limit_bytes > 0.85
        for: 5m
        annotations:
          summary: "容器 {{ $labels.name }} 内存使用率超过 85%"

      - alert: ContainerDown
        expr: absent(container_last_seen{name=~".+"})
        for: 1m
        annotations:
          summary: "容器已停止运行超过 1 分钟"

      - alert: ContainerRestarting
        expr: rate(container_tasks_state{state="running"}[5m]) * 60 < 0
        for: 2m
        annotations:
          summary: "容器频繁重启"
```

# 监控要点

1. **三层监控**：宿主机资源 → 容器 cgroup 指标 → 应用级健康检查
2. **`docker stats`** 适合快速排错，不适合长期监控
3. **cAdvisor + Prometheus + Grafana** 是 Docker 监控的事实标准组合
4. **HEALTHCHECK 是最后一道防线**：在容器级别定义"活着"的标准
5. **告警应聚焦**：CPU 过高、内存泄漏、容器停止、频繁重启
