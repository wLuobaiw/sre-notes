# 何为Docker

**Docker 是一种轻量级的容器化技术**，它允许开发者将应用程序及其所有依赖（库、环境变量、配置文件等）打包成一个标准化单元（称为**容器**），从而实现**"一次构建，随处运行"**。

## 核心概念

| 概念                | 说明                                                         | 类比                   |
| :------------------ | :----------------------------------------------------------- | :--------------------- |
| **镜像(Image)**     | 只读模板，包含运行应用所需的代码、环境和配置（如一个`操作系统+软件`的快照） | 相当于"软件安装包"     |
| **容器(Container)** | 镜像的运行实例（一个轻量化的隔离进程）                       | 相当于"正在运行的软件" |
| **Dockerfile**      | 文本文件，定义如何构建镜像（包含一系列指令）                 | 相当于"菜谱"           |
| **仓库(Registry)**  | 存储和分发镜像的地方（如 Docker Hub）                        | 相当于"应用商店"       |

## 三大核心特性

1. **隔离性**
   - 每个容器拥有独立的文件系统、网络和进程空间
   - 通过 Linux 内核的 **cgroups** 和 **namespace** 实现资源隔离
2. **便携性**
   - 镜像可在任何支持 Docker 的系统中运行（Windows/macOS/Linux/云服务器）
   - 解决经典问题：*"在我电脑上能运行，为什么线上不行？"*
3. **轻量化**
   - 容器共享主机操作系统内核，无需虚拟化完整操作系统
   - 启动仅需**秒级**，资源占用远低于虚拟机

# 使用场景

## 开发与运维的"环境地狱"

假设你是一家电商公司的Java开发工程师小王，公司正在开发一个新的促销系统。让我们看看没有Docker时的开发流程：

### 周一早晨 —— 开发环境搭建 

1. **安装依赖**：你需要安装JDK 8、Maven 3.6、MySQL 5.7和Redis 5.0
   - 花了3小时配置环境，期间遇到：
     - JDK版本冲突（系统已有JDK 11）
     - MySQL安装后无法启动（端口3306被占用）
     - Redis编译安装失败（缺少gcc）
2. **拉取代码**：从Git仓库获取项目后，运行 `mvn install` 报错：
   - "在本地能运行啊" —— 同事老张说
   - 发现老张用的是Maven 3.8，而项目锁定在3.6

### 周三 —— 测试环境部署 

当代码提交到测试环境后：

- 测试报告显示"支付功能异常"
- 排查发现：
  - 测试环境用的是MySQL 8.0（开发用5.7）
  - 某些SQL语法不兼容
  - Redis版本也不同导致缓存序列化问题

### 周五 —— 生产环境上线 

运维团队部署时发现：

- 生产环境的CentOS 7与开发环境的Ubuntu 20.04行为不一致
- 内核参数差异导致线程池表现异常
- 最终导致上线延期2天

## Docker如何解决

开发团队在本地开发完成之后，编写dockerfile，通过docker的自动化部署来直接部署和开发一样的环境

~~~dockerfile
# 开发团队提供的Dockerfile
FROM openjdk:8-jdk
ENV MAVEN_VERSION=3.6.3

RUN apt-get update && \
    apt-get install -y maven=$MAVEN_VERSION && \
    mvn -v

COPY . /app
WORKDIR /app

EXPOSE 8080
CMD ["mvn", "spring-boot:run"]
~~~

### 效果对比

| 问题类型   | 传统方式           | Docker解决方案         |
| :--------- | :----------------- | :--------------------- |
| 环境一致性 | 每台机器环境不同   | 镜像保证环境完全一致   |
| 依赖冲突   | 需要手动解决       | 容器隔离，互不影响     |
| 多版本共存 | 难以实现           | 不同容器可运行不同版本 |
| 环境迁移   | 重新配置，耗时易错 | 一次构建，随处运行     |
| 资源隔离   | 进程相互影响       | 容器间完全隔离         |

# Docker优点

## 环境一致性解决方案

展示了软件开发中典型的"在我机器上能运行"的问题

Docker 通过以下核心技术彻底解决了软件开发中的环境一致性问题：

1. **标准化封装**
   - 将应用程序及其所有依赖（运行时、系统工具、库）打包成单一镜像
   - 镜像包含完整的运行环境，确保从开发到生产的一致性
2. **环境隔离**
   - 每个容器拥有独立的文件系统、网络和进程空间
   - 基于 Linux 内核的 cgroups 和 namespace 实现资源隔离
   - 避免应用间依赖冲突（如不同 Java/Python 版本共存）
3. **跨环境便携性**
   - 镜像可在任何支持 Docker 的平台运行（Windows/macOS/Linux/云）
   - 彻底消除"在我机器上能运行"的问题
4. **高效部署**
   - 容器启动时间：秒级（传统虚拟机需分钟级）
   - 停止/重启：毫秒级响应
   - 资源占用仅为传统虚拟机的 1/5-1/10

## 快速一致的交付流程

**CI/CD 工作流优化** 

| 阶段     | Docker 实现方式                 | 传统方式痛点             |
| :------- | :------------------------------ | :----------------------- |
| **开发** | 本地容器环境与团队共享          | 环境配置差异导致兼容问题 |
| **测试** | 使用相同镜像进行自动化/手动测试 | 测试环境与开发环境不一致 |
| **修复** | 在容器中直接调试并验证          | 难以复现生产环境问题     |
| **部署** | 镜像直接推送到生产环境          | 需重新配置环境，易出错   |

## 弹性扩展能力

**跨平台部署特性** 

- **支持环境**：
  - 开发者本地机器
  - 物理服务器/虚拟机
  - 公有云/私有云/混合云
  - 边缘计算设备
- **扩展模式**：
  - 垂直扩展：快速增加单个容器资源
  - 水平扩展：秒级启动多个容器实例
  - 自动扩缩容：根据负载动态调整容器数量

## 资源利用率提升

**与传统虚拟化对比**：

| 指标     | Docker 容器          | 传统虚拟机         | 优势幅度     |
| :------- | :------------------- | :----------------- | :----------- |
| 启动速度 | 1-3 秒               | 1-5 分钟           | 快 20-100 倍 |
| 磁盘占用 | 10MB-几百MB          | 10GB-几十GB        | 节省 90%+    |
| 内存开销 | 几乎为零（共享内核） | 每个 VM 需独立内存 | 节省 50-80%  |
| 并发密度 | 单机数百容器         | 单机10-20个VM      | 提升 5-10 倍 |

**适用场景：**

- 高密度部署（微服务架构）
- 资源受限的中小型部署
- 需要快速弹性伸缩的业务场景

# Docker架构

Docker 采用经典的 **Client-Server（C/S）架构**，主要由以下组件构成：

```
┌─────────────────────────────────────────────────────┐
│                  Docker Client                      │
│           (docker CLI / docker compose)             │
│             发送命令到 Docker Daemon                  │
└──────────────────────┬──────────────────────────────┘
                       │  REST API (Unix Socket / TCP)
                       ▼
┌─────────────────────────────────────────────────────┐
│                 Docker Daemon (dockerd)             │
│   ┌─────────────────────────────────────────────┐   │
│   │   镜像管理  │  网络管理  │  存储管理  │  进程管理 │   │
│   └─────────────────────────────────────────────┘   │
│                       │                             │
│             通过 gRPC 调用 containerd                 │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│              containerd (容器运行时管理器)             │
│          镜像传输与存储 │ 容器执行与监控                 │
│                      │                              │
│              通过 shim 调用 runc                      │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│                runc (OCI 运行时)                     │
│          创建容器进程 │ 配置 Namespace/Cgroup          │
└─────────────────────────────────────────────────────┘
```

## 各组件职责

| 组件               | 说明                                                         |
| :----------------- | :----------------------------------------------------------- |
| **Docker Client**  | 用户与 Docker 交互的入口，执行 `docker` 命令时实际是向 Docker Daemon 发送 REST API 请求 |
| **Docker Daemon**  | Docker 的核心后台进程（`dockerd`），负责管理镜像、容器、网络和数据卷等全部资源 |
| **containerd**     | 容器运行时管理器，负责容器生命周期管理（创建、启动、停止）、镜像传输与存储。最初从 Docker 中剥离，现为 CNCF 毕业项目 |
| **containerd-shim**| 每个容器对应一个 shim 进程，作为容器进程的父进程，使得 containerd 重启时不影响正在运行的容器 |
| **runc**           | OCI（Open Container Initiative）标准的命令行工具，实际创建容器进程并配置 namespace 和 cgroup |

## 工作流程

1. 用户在终端输入 `docker run nginx`
2. **Docker Client** 将命令转化为 REST API 请求，发送给 **Docker Daemon**
3. **Docker Daemon** 检查本地是否有 `nginx` 镜像，若没有则从 Registry 拉取
4. **Docker Daemon** 调用 **containerd** 的 gRPC 接口，请求创建容器
5. **containerd** 将镜像解压到文件系统，生成 OCI 规格的配置（config.json）
6. **containerd** 通过 **containerd-shim** 调用 **runc** 
7. **runc** 创建容器的 namespace（实现资源隔离）和 cgroup（实现资源限制），启动容器进程
8. **runc** 退出，**containerd-shim** 作为容器进程的父进程持续监控

## Docker vs 虚拟机

| 维度         | Docker 容器              | 传统虚拟机 (VM)            |
| :----------- | :----------------------- | :------------------------- |
| **架构**     | 共享宿主机内核           | 每个 VM 有独立 Guest OS   |
| **隔离级别** | 进程级（Namespace）      | 硬件级（Hypervisor）       |
| **启动时间** | 秒级                     | 分钟级                     |
| **磁盘占用** | MB 级                    | GB 级                      |
| **性能开销** | 接近原生                 | 有一定损耗                  |
| **密度**     | 单机数百个容器           | 单机通常 10-20 个          |
