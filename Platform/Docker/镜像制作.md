# 镜像制作

## 通过容器提交

可以直接将对应容器打包为镜像，使用 `docker commit` 命令来将容器制作成镜像

### docker commit

用于将容器的当前状态提交为新的镜像

```shell
docker commit [选项] 容器 [仓库名[:标签]]
```

**选项** 

- **-a, --author**：指定镜像作者信息（如 `-a "John Doe <john@example.com>"`）
- **-c, --change**：应用Dockerfile指令（支持`CMD`/`ENV`等）
- **-m, --message**：添加提交信息（类似Git commit message）
- **-p, --pause**：提交时暂停容器（默认为true）
- **--format**：指定输出格式（如`json`）
- **--quiet**：只显示新镜像ID

> **注意**
>
> 1. 提交的镜像会包含容器所有可写层的内容
> 2. 新镜像会继承原镜像的历史层
> 3. 敏感信息（如密码）可能被保留在镜像中
> 4. 不适合生产环境（建议使用Dockerfile构建）
> 5. 容器文件系统的临时文件也会被包含

### 制作过程

```shell
# 1. 运行基础容器
docker run -it --name temp ubuntu bash

# 2. 在容器内操作
apt update && apt install -y curl

# 3. 提交为新镜像
docker commit temp my-curl:1.0
```

commit是合并了save、load、export、import这几个特性的一个综合性的命令，它主要做了：

1. 将容器当前的读写层保存成一个新层。
2. 和镜像的历史层一起合并成一个新的镜像
3. 如果原本的镜像有3层，commit之后就会有4层，最新的一层为从镜像运行到commit之间对文件系统的修改。

**缺点**

- 无法版本控制
- 构建过程不透明
- 镜像臃肿

# Dockerfile

## 核心步骤

```shell
# 1. 创建Dockerfile
FROM ubuntu:22.04
RUN apt-get update && apt-get install -y nginx
COPY index.html /var/www/html/
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

# 2. 执行构建
docker build -t my-nginx:1.0 .
```

## 关键指令说明

**操作指令** 

| 指令   | 说明                         |
| ------ | ---------------------------- |
| `RUN`  | 运行指定命令                 |
| `CMD`  | 启动容器时指定默认执行的命令 |
| `ADD`  | 添加内容到镜像               |
| `COPY` | 复制内容到镜像               |

**配置指令** 

| 指令          | 说明                               |
| ------------- | ---------------------------------- |
| `ARG`         | 定义创建镜像过程中使用的变量       |
| `FROM`        | 指定所创建镜像的基础镜像           |
| `LABEL`       | 为生成的镜像添加元数据标签信息     |
| `EXPOSE`      | 声明镜像内服务监听的端口           |
| `ENV`         | 指定环境变量                       |
| `ENTRYPOINT`  | 指定镜像的默认入口命令             |
| `VOLUME`      | 创建一个数据卷挂载点               |
| `USER`        | 指定运行容器时的用户名或UID        |
| `WORKDIR`     | 配置工作目录                       |
| `ONBUILD`     | 创建子镜像时指定自动执行的操作指令 |
| `STOPSIGNAL`  | 指定退出的信号值                   |
| `HEALTHCHECK` | 配置所启动容器如何进行健康检查     |
| `SHELL`       | 指定默认shell类型                  |

## 指令详解

### FROM

**用途**：指定基础镜像
**用法**：`FROM <image>[:<tag>]`
> **注意**：
>
> - 必须是Dockerfile的第一个非注释指令
> - 尽量使用官方镜像和明确版本标签

### RUN

**用途**：执行命令并创建新层
**用法**：

```dockerfile
RUN <command>  # shell格式
RUN ["executable", "param1", "param2"]  # exec格式
```

> **注意**：
>
> - 合并多个操作为单条RUN减少镜像层
> - 记得清理临时文件

### CMD

**用途**：设置容器默认执行的命令
**用法**：

```dockerfile
CMD ["executable","param1","param2"]  # 推荐格式
CMD command param1 param2
```

> **注意**：
> 
> - 每个Dockerfile只能有一条有效CMD
> - 会被`docker run`后面的命令覆盖

### COPY

**用途**：复制本地文件到镜像
**用法**：`COPY <src> <dest>`
> **注意**：
>
> - 源路径是相对于构建上下文的
> - 不会自动解压文件

### ADD

**用途**：增强版COPY（支持URL和解压）
**用法**：`ADD <src> <dest>`
> **注意**：
>
> - 仅当需要自动解压或远程下载时使用
> - 可能造成非预期行为，优先用COPY

### ENTRYPOINT

**用途**：设置容器的主程序
**用法**：

```dockerfile
ENTRYPOINT ["executable", "param1"]
ENTRYPOINT command param1
```

> **注意**：
>
> - 与CMD配合使用（CMD作为参数）
> - 不容易被运行时命令覆盖

### EXPOSE

**用途**：声明容器监听的端口
**用法**：`EXPOSE <port>`
> **注意**：
>
> - 只是文档说明，实际端口映射需用`-p`参数
> - 可以指定协议（如`80/tcp`）

### ENV

**用途**：设置环境变量
**用法**：`ENV <key>=<value>`
> **注意**：
>
> - 会持久化到容器运行时
> - 敏感数据应使用ARG或secrets

### ARG

**用途**：定义构建时的变量
**用法**：`ARG <name>[=<default>]`
> **注意**：
>
> - 只在构建期间有效
> - 通过`--build-arg`覆盖默认值

### VOLUME

**用途**：创建数据卷挂载点
**用法**：`VOLUME ["/data"]`
> **注意**：
>
> - 避免容器层写入大量数据
> - 实际挂载需用`-v`参数

### WORKDIR

**用途**：设置工作目录
**用法**：`WORKDIR /path`
> **注意**：
>
> - 对后续指令生效
> - 使用绝对路径

### USER

**用途**：指定运行用户
**用法**：`USER <user>[:<group>]`
> **注意**：
>
> - 应先创建相应用户
> - 避免使用root

### HEALTHCHECK

**用途**：定义健康检查
**用法**：

```dockerfile
HEALTHCHECK --interval=5m --timeout=3s \
  CMD curl -f http://localhost/ || exit 1
```

> **注意**：
>
> - 检查失败会标记容器为unhealthy
> - 可覆盖默认检查参数

### ONBUILD

**用途**：设置延迟执行的指令
**用法**：`ONBUILD <INSTRUCTION>`
> **注意**：
>
> - 只在被下游镜像构建时触发
> - 适用于基础镜像制作
