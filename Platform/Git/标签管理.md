# 核心概念

## 标签（Tag）的作用

标签（Tag）是为特定提交打上 "里程碑" 标记的引用，通常用于标记版本号（如 `v1.0.0`、`v2.3.1`）。

## 两种标签类型对比

|   类型   |                     特点                     |    适用场景    |
| :------: | :------------------------------------------: | :------------: |
| 轻量标签（Lightweight） | 只是一个指向提交的引用，无额外信息 | 临时标记、个人使用 |
| 附注标签（Annotated） | 独立的 Git 对象，含标签者、日期、说明信息，可用 GPG 签名 | 正式版本发布 |

## 标签与分支的区别

- **标签**：指向固定提交，创建后不可移动（只读里程碑）
- **分支**：指向最新提交，随着新提交自动向前移动

> **总结**：标签是 "快照"，分支是 "流水线"。

# git tag（查看 / 创建 / 删除本地标签）

用于查看本地标签列表、创建新标签或删除已有标签。

```bash
git tag [选项] [<标签名>] [<提交号>]
```

**选项**

### 查看标签

- **无参数**：列出所有本地标签（按字母序排列）
- **-l <pattern>, --list <pattern>**：按模式过滤标签，如 `git tag -l "v1.*"` 列出 v1.x 所有版本
- **-n[N], --list -n[N]**：显示标签的附注信息，N 指定显示的行数（如 `-n3` 显示前 3 行）
- **--sort=<key>**：按指定字段排序，如 `--sort=-creatordate` 按创建时间倒序

### 创建标签

- **-a <标签名>, --annotate <标签名>**：创建附注标签（Annotated Tag），包含作者、日期和附注信息
- **-m <说明>, --message <说明>**：配合 `-a` 指定附注信息（避免打开编辑器）
- **-s <标签名>, --sign <标签名>**：创建 GPG 签名的附注标签，用于验证标签真实性
- **-u <keyid>, --local-user <keyid>**：使用指定的 GPG 密钥进行签名
- **-f, --force**：强制覆盖已存在的同名标签
- **<提交号>**：给历史提交打标签（不指定则默认给 HEAD 打标签）
- **无 -a/-s**：创建轻量标签（仅一个指向提交的引用）

### 删除标签

- **-d <标签名>, --delete <标签名>**：删除指定的本地标签

> **注意**
>
> 1. 正式版本发布推荐使用附注标签（`-a` + `-m`），记录版本说明和发布信息
> 2. 标签名通常遵循语义化版本规范：`v1.2.3`（主版本.次版本.修订号）
> 3. 创建附注标签时务必加 `-m` 写说明，否则会打开编辑器等待输入
> 4. 可以为历史提交补打标签，只需在末尾指定对应的提交号
> 5. `-f` 会静默覆盖本地同名标签，操作前请确认无误

**示例**

```bash
# 列出所有标签
git tag

# 按模式过滤（列出 v2.x 所有版本）
git tag -l "v2.*"

# 创建轻量标签（指向当前 HEAD）
git tag v1.0.0

# 创建附注标签（带说明）
git tag -a v1.0.0 -m "正式发布 v1.0.0 版本"

# 给历史提交打标签
git tag -a v0.9.0 -m "v0.9.0 预发布版本" a1b2c3d

# 创建 GPG 签名的标签
git tag -s v1.0.0 -m "正式发布 v1.0.0"

# 强制覆盖已存在的标签
git tag -f v1.0.0 HEAD

# 删除本地标签
git tag -d v0.9.0

# 按创建时间倒序查看标签及附注信息
git tag -n --sort=-creatordate
```

# git push（推送标签到远程）

用于将本地标签推送到远程仓库。默认情况下，`git push` **不会** 自动推送标签，需要显式指定。

```bash
git push <远程仓库名> [<标签名> | --tags | --follow-tags]
```

**选项**

- **<远程仓库名> <标签名>**：推送单个指定标签到远程，如 `git push origin v1.0.0`
- **--tags**：推送所有本地标签（包括轻量标签和附注标签）到远程
- **--follow-tags**：只推送附注标签（推荐，避免推送临时的轻量标签）
- **--no-tags**：推送时明确不推送任何标签
- **--atomic**：全部推送成功才生效，防止部分推送失败导致状态不一致

> **注意**
>
> 1. `git push` 默认**不会**推送标签，需要显式指定，这是与分支推送的重要区别
> 2. 生产环境中推荐使用 `git push --follow-tags` 替代 `--tags`，避免将临时轻量标签推送到远程
> 3. 推送单个标签是最精确的方式：`git push origin v1.0.0`
> 4. 如果远程已有同名标签，推送会失败，必须先删除远程标签或使用 `-f` 覆盖

**示例**

```bash
# 推送单个标签到远程
git push origin v1.0.0

# 推送所有本地标签
git push origin --tags

# 只推送附注标签（生产环境推荐）
git push --follow-tags

# 推送时不带任何标签
git push --no-tags
```

# 删除远程标签

用于删除远程仓库中已存在的标签。

```bash
# 方式一：使用 --delete 明确删除
git push <远程仓库名> --delete <标签名>

# 方式二：推送空引用覆盖标签
git push <远程仓库名> :refs/tags/<标签名>
```

**推荐完整流程**

```bash
# 1. 先删除本地标签
git tag -d v0.1.0

# 2. 再删除远程标签
git push origin --delete v0.1.0
```

> **注意**
>
> 1. 删除远程标签前**务必先删除本地标签**，避免误操作后重新推送
> 2. 方式一（`--delete`）语义更清晰，推荐使用
> 3. 方式二（`:refs/tags/<标签名>`）是 Git 的 "推送空引用" 语法，含义为 "将远程的标签引用置空"
> 4. 删除远程标签属于 "重写历史" 操作，在多人协作仓库中需要提前告知团队成员

# 检出标签

用于将工作区切换到标签对应版本的代码。检出标签会进入 "分离头指针"（detached HEAD）状态。

```bash
git checkout <标签名>
```

**注意事项**

1. 处于分离头指针状态时，HEAD 不再指向任何分支，而是直接指向某个提交
2. 在此状态下做的修改**不会**更新标签（标签是不可移动的）
3. 如需在标签版本基础上继续开发，应基于标签创建新分支

**示例**

```bash
# 检出 v1.0.0 版本的代码（只读查看）
git checkout v1.0.0

# 基于标签创建新分支进行开发（推荐）
git checkout -b hotfix-from-v1.0 v1.0.0
```

> **注意**
>
> 1. 在标签上直接修改并提交，新的提交将无法通过分支名访问，容易丢失
> 2. 如果希望修复某个历史版本的 bug，建议先基于标签创建修复分支，再在分支上修改
> 3. 分离头指针下的提交可以被分支引用回收（gc），因此如需保留修改请务必创建分支

# 查看标签详情

用于查看标签的详细信息，包括指向的提交内容、附注信息、GPG 签名验证等。

```bash
# 显示标签指向的提交详情及附注信息
git show <标签名>

# 验证 GPG 签名的标签
git tag -v <标签名>
```

**示例**

```bash
# 查看 v1.0.0 标签详情
git show v1.0.0

# 验证 v1.0.0 的 GPG 签名
git tag -v v1.0.0
```

> **注意**
>
> 1. `git show` 对轻量标签显示指向的提交差异，对附注标签还会额外显示标签元信息（标签者、日期、附注说明）
> 2. `git tag -v` 需要 GPG 密钥公钥才能完成验证，若无对应公钥会提示 "无法找到公钥"
