
# 是什么

DaemonSet 确保**每个节点运行一个 Pod 副本**。新增节点时自动部署，移除节点时自动回收。副本数与节点数严格绑定，不由用户指定 replicas。

# 与 Deployment 的根本区别

Deployment 的 replicas 是**绝对值**（`replicas: 3`，无论集群有多少节点）。DaemonSet 是**按节点计算**，集群扩容到 20 个节点就自动有 20 个 Pod。

这意味着两者的适用场景完全不同：

- Deployment：业务应用，副本数由**流量**决定
- DaemonSet：节点级系统服务，每个节点都需要

# 为什么非要每个节点一个？

因为某些服务采集的是**节点级别的信息**，或者必须代理**本节点的网络流量**。如果少部署了一个节点，那个节点的数据就丢了。

# 典型场景

| 场景 | 示例工具 | 原因 |
|------|---------|------|
| 日志采集 | Filebeat、Fluentd | 每节点有一个容器日志目录，必须在本地读取 |
| 监控指标采集 | Node Exporter、Datadog Agent | 采集的是节点级指标（CPU、内存、磁盘、网络） |
| 网络插件 | Calico、Flannel、Cilium | 每个节点都需要网络代理 |
| 存储插件 | CSI 驱动的 Node Plugin | 每个节点需要挂载存储卷的能力 |

# DaemonSet 的调度

即使 DaemonSet 默认在所有节点运行，也可以用 `nodeSelector`、节点亲和、污点容忍来控制只在**特定节点子集**上运行。比如只在 GPU 节点上部署 GPU 监控 agent。相关调度概念详见 [污点与容忍](../调度/污点与容忍.md) 和 [亲和与反亲和](../调度/亲和与反亲和.md)。
