
# 是什么

Labels（标签）是附加在 Kubernetes 对象上的键值对，用于组织和筛选资源。几乎所有 Kubernetes 资源（Pod、Service、Deployment、Node 等）都有 `metadata.labels`。

标签是任意字符串，Kubernetes 不强加预定义含义 —— 用户根据自己的业务逻辑来组织。

# 为什么需要标签

Kubernetes 集群中有大量 Pod，不能靠名字管理。标签提供了一种灵活的筛选机制：给资源打上业务含义的记号，然后用选择器（Selector）找到它们。

# 创建方式

标签在资源的 `metadata` 中定义，不在 `spec` 中：

```yaml
kind: Pod
metadata:
  name: nginx-pod
  labels:            # ← 标签在这里
    app: nginx
    env: prod
spec:
  containers:
  - name: nginx
    image: nginx:1.21
```

`metadata` 是所有 Kubernetes 资源的公用部分，任何资源都可以有标签。

# 工作负载控制器如何管理标签

Deployment/StatefulSet/DaemonSet/Job 创建 Pod 时，Pod 的标签来自 Pod 模板。控制器内部有三层标签概念：

| 位置 | 作用 |
|------|------|
| `metadata.labels` | 控制器**自身**的标签 |
| `spec.selector.matchLabels` | 控制器用来**找到**自己管理的 Pod（Selector） |
| `spec.template.metadata.labels` | 创建的 Pod **被贴上**什么标签（模板） |

**关键约束**：`spec.template.metadata.labels` 必须包含 `spec.selector.matchLabels` 中的所有标签。否则控制器无法识别自己创建的 Pod，会不断创建新 Pod 直到资源耗尽。所有工作负载控制器（Deployment、StatefulSet、DaemonSet、Job/CronJob）都遵循此规则。

控制器每创建一个 Pod，自动将 `template.metadata.labels` 贴上去。用户不需要手动管理。

# Selector（选择器）

Selector 是按标签条件筛选资源的选择器。几乎所有 Kubernetes 资源都用 Selector 关联 Pod：

- Service → `selector` → 流量转发到匹配的 Pod
- Deployment → `spec.selector` → 管理匹配的 Pod
- NetworkPolicy → `podSelector` → 规则作用在匹配的 Pod 上

同一个标签可以被多个 Selector 引用，互不冲突。

## 两种语法

**等值匹配**：`app=nginx`（精确等于）、`env!=prod`（不等于）、`env in (staging, dev)`（在集合中）

**集合匹配**：在等值基础上支持 `notin`、`exists` 等操作。ReplicaSet 支持、ReplicationController 不支持 —— 这是 RS 代替 RC 的唯一功能差异。

# 社区推荐标签

生态工具（监控、日志、可视化）遵循一套约定标签，虽然不是强制但建议使用：

| 标签 | 含义 |
|------|------|
| `app.kubernetes.io/name` | 应用名称 |
| `app.kubernetes.io/instance` | 实例标识（区分同应用的多套部署） |
| `app.kubernetes.io/version` | 应用版本 |
| `app.kubernetes.io/component` | 组件角色（frontend / backend / database） |
| `app.kubernetes.io/part-of` | 所属系统 |
| `app.kubernetes.io/managed-by` | 管理工具（Helm / Kustomize） |
