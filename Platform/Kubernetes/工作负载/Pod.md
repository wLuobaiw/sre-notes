
# 是什么

Pod 是 Kubernetes 中**最小的调度和部署单元**。一个 Pod 包含一组（一个或多个）紧密耦合的容器，这些容器共享网络命名空间和存储卷，且**一定运行在同一台机器上**。

在 Docker 中直接操作的是容器，在 Kubernetes 中操作的是 Pod —— 容器必须包在 Pod 里才能运行。

# 为什么存在

Kubernetes 不直接管理单个容器的原因：**有些容器天生就需要紧密协作**。例如 Web 应用输出日志到文件，旁边的 Filebeat 读取日志并上报。如果放在两个独立的容器里，就需要额外配置网络和存储才能协作。

Pod 把这种"应该绑在一起"的容器打包成一个整体：

- **共享网络命名空间** —— 容器间用 `localhost` 通信，Pod 有唯一 IP
- **共享 IPC 命名空间** —— 可以用 System V 信号量或 POSIX 共享内存通信
- **共享存储卷** —— 容器之间共享数据，零网络开销
- **原子调度** —— 整个 Pod 要么在一台机器上，调度器不把一个 Pod 拆到两台机器

这种"主容器 + 辅助容器"的架构叫 **Sidecar 模式**。

# Pause 容器

每个 Pod 启动时，Kubernetes 会最先启动一个特殊的 **Pause 容器**（也叫 Infra 容器），它做两件事：

1. 创建并持有网络命名空间（Pod IP 的来源）
2. 整个 Pod 生命周期内一直存活

Linux 命名空间在没有进程时会自动销毁。如果业务容器崩溃重启导致网络命名空间消失，Pod IP 就会变。Pause 容器一直活着，占住网络命名空间，不管业务容器怎么重启，Pod IP 始终保持不变。其他容器启动后加入 Pause 容器的网络命名空间。

Pause 容器极轻量 —— 只调用 `pause()` 系统调用把自己挂起，几乎不消耗资源。

# Init 容器

Init 容器是 Pod 中**在业务容器启动之前**运行的容器。一个 Pod 可以有多个 Init 容器，它们按顺序执行，**前一个成功后才会执行下一个**。

典型用途：
- 等待依赖服务就绪（比如等数据库启动）
- 初始化配置、下载依赖文件
- 执行数据库迁移

Init 容器的关键特性：
- **必须全部成功，Pod 才会进入运行阶段**。任一 Init 容器失败，整个 Pod 会被重启
- 每个 Init 容器重启时，所有 Init 容器从头执行
- Init 容器的镜像可以与业务容器不同，这意味着可以使用独立的工具镜像

# 三种探针

Kubernetes 通过探针检查 Pod 内容器的健康状态。三种探针的核心区别在于**失败后的行为**：

| 探针 | 回答的问题 | 失败后 |
|------|-----------|--------|
| Startup Probe | 应用启动完了吗？ | 阻断其他探针，直到成功 |
| Liveness Probe | 进程还活着吗？（是否死锁） | **杀掉容器，重启** |
| Readiness Probe | 能否正常处理请求？ | **从 [Service](../服务与网络/Service.md) 摘除**，不杀容器 |

**Startup Probe 成功之前，Liveness 和 Readiness 不工作**。这对于启动慢的应用至关重要 —— 否则 Pod 还没启动完就被 Liveness 判定为"死了"，陷入无限重启循环。

**Readiness 失败 ≠ Liveness 失败**：Readiness 失败是"暂时不可用"（如依赖的数据库断了），不该被杀掉；Liveness 失败是"进程已死"（如死锁），必须重启。实践中常犯的错误是把两者配成一样的检查。

# Pod 生命周期

Pod 的生命是**单向的**，不可逆：

```
Pending → Running → Succeeded / Failed
```

## 各阶段含义

- **Pending**：Pod 已被 API Server 接受，但容器尚未完全运行。可能正在拉取镜像、等待调度
- **Running**：Pod 已绑定到节点，至少一个容器仍在运行
- **Succeeded**：所有容器正常退出（exit code 0），且不会重启。常见于 [Job](Job与CronJob.md)
- **Failed**：所有容器终止，且至少一个以非零退出码终止

## 特殊状态

- **Unknown**：节点失联，kubelet 无法上报 Pod 状态
- **CrashLoopBackOff**：容器反复崩溃后，Kubernetes 会指数级延迟重启间隔（10s → 20s → 40s → ...，上限 5 分钟）

## 容器重启策略

Pod 的 `restartPolicy` 决定容器退出后如何处理：

- **Always**（默认）：总是重启。适用于长期运行的服务（[Deployment](Deployment与ReplicaSet.md)）
- **OnFailure**：仅失败时重启。适用于 Job
- **Never**：从不重启。适用于一次性任务
