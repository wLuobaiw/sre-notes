
# 是什么

污点（Taint）和容忍（Toleration）是 Kubernetes 的**反向调度机制**。亲和是 Pod 主动选择节点（"吸"），污点是节点拒绝 Pod（"推"）。

节点被打上污点后，只有具备对应容忍的 Pod 才能调度上来。两者在调度流程的**预选阶段**起作用：无容忍的 Pod 直接被淘汰。

# 污点的三种效果

| 效果 | 行为 |
|------|------|
| **NoSchedule** | 新 Pod 不能调度到这个节点 |
| **PreferNoSchedule** | 尽量不调度到这个节点（软性，实在没节点才会放） |
| **NoExecute** | 新 Pod 不能调度，**已在运行的 Pod 也会被驱逐**（除非有对应容忍） |

# 容忍的配置

Pod 可以在 spec 中声明容忍来匹配节点的污点：

- `key` / `operator` / `value` / `effect`：匹配污点的条件
- `tolerationSeconds`：仅对 NoExecute 有效。Pod 在节点被打上 NoExecute 污点后，容忍一段时间（如 300 秒）才被驱逐。用于给应用优雅关闭的时间窗口

# 集群自动加的污点

[kube-controller-manager](../控制平面/kube-controller-manager.md) 中的节点控制器在节点出问题时自动打污点，保证 Pod 被及时迁移：

| 污点 | 触发条件 |
|------|---------|
| `node.kubernetes.io/not-ready` | 节点 NotReady |
| `node.kubernetes.io/unreachable` | 节点失联 |
| `node.kubernetes.io/disk-pressure` | 磁盘空间不足 |
| `node.kubernetes.io/memory-pressure` | 内存不足 |
| `node.kubernetes.io/pid-pressure` | PID 不足 |

这些污点使用 NoExecute 效果，配合默认的 `tolerationSeconds: 300`（5 分钟），确保临时故障不会立刻触发大规模 Pod 迁移。

# 典型场景

- GPU 节点打污点 `nvidia.com/gpu:NoSchedule`，只有 GPU 任务的 Pod 有容忍才能调度
- 专用节点：某些节点只跑特定业务，其他业务 Pod 无容忍无法上来
- 维护操作：手动给节点打 NoExecute 污点，Pod 被驱逐后在其他节点重建，实现无停机维护

# 与亲和的关系

| | 方向 | 作用阶段 | 
|------|------|------|
| 污点 | 节点 → Pod（推） | 预选 |
| [亲和](亲和与反亲和.md) | Pod → 节点（吸） | 预选 + 优选 |

一个 Pod 要成功调度到节点上，必须**同时满足**污点容忍和节点亲和（如果有要求）。
